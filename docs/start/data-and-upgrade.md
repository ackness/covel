# 数据、备份与升级

这一页说明桌面版把东西存在哪里，怎样备份，以及升级前要检查什么。

## 文件在哪里

桌面版第一次启动时创建 `~/.covel/`。小的配置文件在这个目录里，占空间的数据默认在它下面的 `data/` 里。

```text
~/.covel/                 配置
  config.toml             数据位置、网络代理、日志参数
  llm.toml                模型用途配置（可选）
  keys.env                服务商 API 密钥，明文
  settings.json           界面里的设置：语言、外观、模型绑定、插件设置
  plugins/                你安装的插件

~/.covel/data/            数据（位置可以修改）
  covel.db                存档数据库
  media/                  已保存的图片、音频等媒体
  worlds/                 你安装和创建的世界
  logs/                   日志
    desktop.log           桌面程序自身的日志
    server.log            后端的日志
```

不想翻目录的话，**设置 → 桌面** 列出了所有路径，可以一键打开。

## 把数据放到别的磁盘

在 **设置 → 桌面** 里切换数据目录，或者编辑 `~/.covel/config.toml`：

```toml
[paths]
data_root = "/Volumes/External/covel-data"
```

在设置里选好新目录后，Covel 会问你要不要把现有数据带过去：

- **复制我的数据**：退出并重新打开 Covel。它在启动时把存档数据库、`worlds/` 和 `media/` 复制到新位置，复制成功后才切换过去，并弹窗告诉你结果。
- **从空目录开始**：重启后使用新位置，里面没有你的数据。
- 新目录里已经有 Covel 数据时，不会问你，也不复制：重启后直接使用那里的数据，不覆盖任何文件。

不管选哪个，旧目录里的内容都不会被移动或删除。复制失败时 Covel 继续使用旧目录，并弹窗说明原因。

> [!NOTE]
> 手动编辑 `config.toml` 不会复制数据，改完需要重启 Covel。新位置里没有数据时是空的，原来的存档和世界留在原处。想带过去，先退出 Covel，再按下面“备份”一节复制数据库、`worlds/` 和 `media/`。

## 备份

备份前先退出 Covel。数据库在运行时还有两个伴随文件，需要一起复制。

| 要备份的内容       | 复制什么                                                                |
| ------------------ | ----------------------------------------------------------------------- |
| 存档               | `covel.db`，以及同目录下的 `covel.db-wal` 和 `covel.db-shm`（如果存在） |
| 你的世界           | `data/worlds/` 整个目录                                                 |
| 你安装的插件       | `~/.covel/plugins/` 整个目录                                            |
| 模型和界面设置     | `settings.json`、`llm.toml`                                             |
| 密钥               | `keys.env`。它是明文，请放在安全的地方                                  |
| 已保存的图片和音频 | 当前数据目录下的 `media/` 整个目录                                      |

恢复时，把数据库和 `media/` 一起放在新数据目录下，再打开 Covel。如果之前复制时漏了媒体，先手动从旧目录复制 `media/`；旧目录中的文件已删除且没有备份时，无法恢复。

只想备份界面设置时，可以用 **设置 → 数据** 里的“导出设置”，得到一个 JSON 文件。默认不包含 API 密钥。

> [!CAUTION]
> 不要在 Covel 还在运行时单独移动或删除 `covel.db-wal` 和 `covel.db-shm`，这会损坏存档。

## 升级之前

Covel 还在早期阶段，版本之间可能有不兼容的改动，而且**存档不会自动迁移**。每次升级前：

1. 读这个版本的[更新日志](../CHANGELOG.md)，找到“升级说明”和“破坏性变更”。
2. 按上面的方法做一次完整备份。
3. 如果更新日志说明旧数据库不能继续使用，升级后需要新建存档；旧的备份留着，以便回到旧版本。

Covel 启动时会检查存档数据库是哪个版本写的。当前版本打不开时，启动页会显示“数据来自另一个 Covel 版本”，Covel 不会改动这个数据库。这时：

1. 退出 Covel，备份数据目录。
2. 按上面[把数据放到别的磁盘](#把数据放到别的磁盘)的做法，在 `config.toml` 里把 `data_root` 改成一个新的空目录。
3. 重新启动 Covel，从空目录开始。想继续玩旧存档，就回到写入它的那个版本。

桌面版启动时会检查有没有新的正式版本。有的话会弹出提示，你可以“前往下载”或“忽略此版本”。它不会自动下载或安装。

## 日志

出问题时，先看 `~/.covel/data/logs/` 下的两个文件：

- `desktop.log`：窗口、启动和后端进程监控的日志。
- `server.log`：后端的输出和请求日志。

日志文件写满后会换新文件，默认每个文件 10 MB，保留 10 份。每个回合里模型请求和工具调用的细节不写入这些文件，它们在应用的调试页面里。
