# 世界美术方向与验收

三个在用世界共享交付质量，不共享一种画风。美术应让玩家在选世界时预期到正确的玩法，并在进入后保持人物、地点与规则可信。

下表是基于题材和现有资源的设计定位，尚未经过玩家访谈或转化率实验。它不限制玩家的年龄、性别或文化背景。

| 世界      | 优先传达的体验与玩家兴趣                                   | 视觉语言                                                              | 主要展示方式                                     |
| --------- | ---------------------------------------------------------- | --------------------------------------------------------------------- | ------------------------------------------------ |
| 遥风学园  | 对话、慢热关系、群像与学园祭；喜欢视觉小说和日常陪伴的玩家 | 清透动漫线稿与柔和赛璐珞；海蓝、薄荷绿、樱粉；夜间蓝紫环境光搭配暖灯  | 透明人物立绘，五组固定机位的昼夜场景             |
| 雾港      | 线索、阵营、风险和未知；喜欢悬疑调查、暗奇幻与探索的玩家   | 写实绘画感的海港 noir；冷灰、青灰、旧铜与铁锈；雾中近景清楚、远景消失 | 半身人物卡与遗迹港口封面，配合传统叙事           |
| Emberback | 修复设施、协作求生与时间谜团；喜欢科幻探索和技术冒险的玩家 | 明亮复古工业科幻插画；奶油白、陶土、钴蓝；低角度亮侧光与冷色暗侧边光  | 带职业环境的成人全身像，中继站封面，配合传统叙事 |

雾港的姓名与叙事语境不自动要求更换现有面孔或全部改成古装。Emberback 的温暖、实用和社区感也是题材特征；不要仅因“科幻”就改成冰冷舰桥、军装或霓虹。归档的 Cloudmere 与 Neonridge 不在当前可玩美术集内，恢复上架时再按其设定独立验收。

## 每个世界的视觉不变量

### 遥风学园

- 角色靠发型、表情和职业道具区分：澪的稿纸，凛的采访本与相机，夏帆的木吉他，悠真的眼镜与文件夹，遥的日程本，千寻的粉笔与旧书，奏太的鼓棒，茜的书与干花。
- 延续已批准的藏蓝校服、白色滚边和各角色现有轮廓，不在表情变体中随机切换水手服、西装、发饰或蝴蝶结。制服的一致性来自共同色系和角色稳定性。
- 千寻是成年教师，学生是高中生。`teen-appropriate` 指内容尺度；教师应保留成人身份、职业着装与温和引导姿态。
- 日景是空间母版。夜景只改变光照、天空和原有灯具状态，保留镜头、地平线、门窗、楼层、书架、路面和道具位置。不因入夜自动下雨。
- 社团楼始终三层、瓦顶、右侧攀藤；教室窗侧课桌与前景笔记本固定；图书馆夹层与右侧长桌固定；海堤坡道右侧贩卖机固定；商店街保持书店/花店在左、餐厅/乐器店在右的既定机位。
- 背景承接人物表演。前景和对话框区域保持可读，夜景保留中间亮度，不把温柔日常做成惊悚场景。

### 雾港

- 永雾、悬崖、三层港城、涨退潮与盐蚀材质构成地点身份。场景内的能见度应短，远景用模糊轮廓暗示；宣传封面的城市总览是题材概览，不代表玩家在雾中能看清整座城。
- 人脸与一件标志道具先被读到，黑色衣料要保留层次。不要为了“黑暗”把所有脸都压黑，也不要用华丽法术抢走线索和人物的注意力。
- 铁姑的雾蚀在**角色自身左臂**肘部以下；禁止把画面左侧当作解剖左侧。右臂保持正常。局部半透明的灰雾不是冰甲、雷电或机械义肢。
- 灰隼下潮装备使用遮光、低亮度的潮石冷光，不使用裸露火焰。城内安全地点的暖色灯火与探险装备要区分。
- 小霜的开局雾蚀只在指尖偶尔透光。齐老的双手半透明程度更重；不要把所有角色都画成同一种发光法师。具体程度以角色卡为准。
- 服装差异体现身份：公会的严谨、议会的旧权威、盐牙的实用磨损、雾使的朴素。维持现有角色身份，不用统一美型削弱年龄和经历差异。

### Emberback

- 潮汐锁定行星的亮侧、暮光带和暗侧是空间分区。不要套用地球“白天/夜晚换天空”的通用模板；未来需要场景变体时，优先表现风暴、电力与通信状态。
- Tomas 的搪瓷杯与电台、June 的围巾与车钥匙、Mina 的频谱仪是人物识别点。保留年龄、肤色、脸形与职业姿态。
- 中继站的陶瓷隔热件、重复维修的设备、模拟仪表、六轮爬行车与玄武岩地貌比无用途的齿轮、装甲或太空服更能表达世界。
- 角色周围的维修间、站坪和观测台是传统叙事人物卡的一部分。它们不是透明舞台素材；保留这种差异，不为整齐而抠除所有环境。
- 明亮不等于没有危险：警报、设备损坏、风暴边缘与长阴影提供悬疑，人物仍然具有可接近的社区气质。

## 生成与交付

1. 先读 `WORLD*.md`、角色卡与 `data/dimensions.yaml`，再检查现有图片。清单提示词和图片发生冲突时，应修正冲突，不能只更新文字就宣称图片已达标。
2. 新人物、新地点可按 `portraits.json` / `scenes.json` 的共享风格与独立主体生成。共享提示词只能减少风格漂移，不能保证身份和布局一致。
3. 已有人物的表情/服装变体与已有场景的时段变体，使用批准图作为编辑输入，并逐条锁定不变量。批量生成脚本目前是文字生成，不会自动读取参考图。
4. 使用内置 imagegen 时不需要项目 provider key；仓库 CLI 是另一条显式配置的生成方式。本轮批准的完整编辑提示词和输入版本见 [提示词记录](./world-art-prompts.json)。
5. 人物 PNG 为 `1024x1536`，当前场景 PNG 为 `1536x1024`。透明立绘必须有真实透明像素，不能只有全不透明的 alpha 通道，也不能把棋盘格画进图片。
6. 检查原尺寸、缩略图、浅深背景合成、移动端裁切及昼夜对照。图片不应带说明文字、水印或未校对的招牌；必须出现的文字优先交给 UI。
7. 替换已批准资产前保留原件或 Git 版本。选定图复制到世界包，在发布前刷新 `presence*.json` 与 `scenes.registry.json` 的 SHA-256 和字节数。中英文 presence 必须引用相同的图片内容，显示名称仍按语言保留。

```bash
node scripts/emit-presence.mjs mistport
node scripts/emit-scenes.mjs haruka-academy
pnpm --filter @covel/server exec vitest run tests/lib/world-art-assets.test.ts
pnpm exec tsx scripts/validate-release-worlds.ts worlds/emberback worlds/mistport worlds/haruka-academy
```

`emit-presence` 写入默认语言文件；如果有本地化 `presence.*.json`，还需同步媒体引用并保留本地化名称。资源测试覆盖所有这些文件，避免只更新中文图而让英文会话继续引用旧哈希。

当前封面位于 `apps/web/public/visuals/worlds/`，由 `apps/web/src/lib/world-visuals.ts` 选择，不会因为世界包内人物图更新而自动更换。封面与玩法相符且质量合格时可以保留；世界包的导入协议见 [world-data](../reference/world-data.md)，媒体引用见 [media-store](../reference/media-store.md)。

## 后续美术投入顺序

这些是待验证的建议，不是本轮已制作或已接入的资源：

| 世界      | 优先增加的内容                                                     | 验证它是否有效                                   |
| --------- | ------------------------------------------------------------------ | ------------------------------------------------ |
| 遥风学园  | 澪/悠真/茜的克制情绪变体，以及学园祭前夜的布置变化                 | 玩家能否在不读标签时辨认同一角色、情绪与祭典进度 |
| 雾港      | 主栈桥、公会鉴定台、退潮入口等线索插画；以潮位而非普通昼夜区分状态 | 玩家能否看出调查对象、安全边界和撤离压力         |
| Emberback | 信号维修间、爬行车站坪、Nightglass；以正常/断电/风暴将至区分状态   | 玩家能否理解设备状态和下一步可行动的地点         |

先观察不同兴趣玩家对三张世界卡的选择理由，再观察进入后是否符合预期、是否愿意完成首个目标。审美判断不能替代这些体验证据，也不应为追求同一套视觉小说资源数量而改变世界玩法。
