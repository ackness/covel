# Upgrade from v0.0.41 to v0.0.42

> [中文版](./upgrade-0.0.42.md)

v0.0.42 replaces development-stage plugin, world-data, and persistence contracts. **It does not automatically convert v0.0.41 databases, sessions, snapshots, or browser checkpoints.** Keep the old application and a complete data backup, start v0.0.42 with isolated new storage, and create new sessions. Creating a session alone cannot repair an old database schema. This guide is for users, operators, and external plugin/world authors; the linked current references define the exact fields.

## Preserve the old environment first

1. Record the old application version, actual storage backend, database and media locations, browser origin/profile, and installed plugins and worlds. Stop every server, desktop process, and worker using the old database, and confirm writes have stopped.
2. Back up the old app or installer, configuration, settings, and installed plugins and worlds. For desktop, back up the configuration root (normally `~/.covel/`) and the actual `<data_root>`; `[paths].data_root` in `config.toml` may redirect it. `keys.env`, environment files, and browser keys can contain credentials: keep backups access-restricted and never paste them into tickets or logs.
3. For SQLite, back up the database together with any matching `-wal` and `-shm` files. Do not copy only the main file or separately move the companion files while a process holds the database open. The source server uses the actual `SQLITE_PATH`; its default development path is in the [environment guide](env-registry.md#plugin-extension-development-data). Desktop defaults to `<data_root>/covel.db`.
4. Include media bytes: SQLite/local-fs media may use a configured `MEDIA_ROOT`; PostgreSQL media may reside in the database; browser-local media resides in IndexedDB. Check the actual backend rather than backing up metadata alone. Use a database-administrator-approved consistent PostgreSQL backup and include application volumes and external media. Docker Compose may use both `appdata` and `pgdata18`; `pnpm docker:down-all` deletes volume data.

Verify that backup files are readable and the database backup can be restored, and keep the original backup. This guide does not require wiping all settings: ordinary settings persistence accepts only the current `schemaVersion: 2`. Unversioned or v1 development data is rejected while the original content is preserved; rebuild affected settings after backup. Keys use a separate channel, so confirm that they can be securely reconfigured without adding them to an ordinary settings export.

## Start with new data

| Environment                      | v0.0.42 action                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Desktop                          | Quit the old app and back up the directories above. Before the new app uses the old database, point `[paths].data_root` to a **new directory without the old database**, then start it; retain the old `<data_root>` for rollback. The configuration root still holds `config.toml`, `settings.json`, `llm.toml`, `keys.env`, and `plugins/`; inspect old settings and plugins there. See [desktop configuration](desktop-config.en.md).                                                                                                                                                                           |
| Source / ordinary server, SQLite | Stop old processes and back up the database/WAL/SHM and media. Set `SQLITE_PATH` to a nonexistent new database file; start the current server to create the current schema. Confirm effective `STORE_BACKEND`, `MEDIA_ROOT`, and related settings. If reusing the old media root, verify its backup and references before cleanup of any shared content.                                                                                                                                                                                                                                                           |
| PostgreSQL / Docker              | Deploy the current schema to a **new empty database**, or use a separately designed and reviewed SQL migration that was tested on a backup copy. Generated initial DDL is not an old-database upgrade script. Preserve the old database, volumes, and external media backups. Confirm both the Compose `DATABASE_URL` and volume mappings before startup. See [database maintenance](env-registry.md#数据库维护命令) and [store transactions](../reference/transactions.md#schema-migrations).                                                                                                                     |
| Browser local mode               | Authoritative session/world data live in `covel-browser-vault` IndexedDB for that origin; media/cache and some application data live in `covel-browser-cache`. Ordinary settings use localStorage and keys are separate. Back up the old browser profile/site data; use the new version in an **independent browser profile or origin** and create new sessions. Do not import old checkpoints directly or treat “clear site data” as a backup. Remote mode also requires the server-backend steps. See [storage architecture](../architecture/storage.md) and [SettingsStore](../reference/settings-store.en.md). |

Old SQLite `lorebook_entries` uses `plugin_id`; the current schema requires `owner`. `CREATE TABLE IF NOT EXISTS` does not change the old table, and index creation can fail with `no such column: owner`. Creating or deleting sessions or resetting browser checkpoints cannot fix that table. Other old backend schemas are not guaranteed to start either. **Do not treat old sessions, memory, execution results, exports, queued jobs, or snapshots as current-format data.** Reimport updated world packages and recreate sessions and snapshots in the new store; an old checkpoint is not a compatible recovery point. Retain old backups for inspection or a separately developed migration. The [development-data note](env-registry.md#plugin-extension-development-data) documents the known boundary.

Updating source or an installer does not rewrite installed external plugins and worlds. Back up their installed directories, then upgrade or reinstall versions that **pass the v0.0.42 loader**; discovery may skip old packages. A fresh database alone leaves incompatible installed packages in place. See [plugin installation](../reference/plugin-installation.md). Desktop defaults to a `plugins/` directory under the configuration root and a `worlds/` directory under `<data_root>`.

## Plugin and world author checklist

| Old form or assumption                                                                                                           | Current contract and action                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| -------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Flat manifests or multiple child `PLUGIN.md` files; package and runtime treated as one object                                    | The root `PLUGIN.md` declares package identity, `provides/requires/optional/conflicts`, schemas, and `contributes`. Multiple runtimes use `runtimes/<id>/RUNTIME.md`; a single runtime may use root `runtime`, and a package may have none. `loadPluginDefinition()` returns `packageManifest` and `manifests`; use `loadPluginUi()` and stop reading the old `definition.plugin`/primary `manifest` mirrors. Register entry/UI/events/extensions once per package. See [plugin contracts](../reference/plugins.md#包与运行时文件).                                               |
| Cross-package dependencies use concrete runtime IDs; a bare `provides` claim is assumed to implement a kernel extension point    | Use versioned contracts for cross-package inputs and `needs`, declared in root `requires` or `optional`; within-package runtime IDs remain valid. Declare extensions in root `contributes.extensions` and register them in entry code; kernel dependencies resolve actual implementations. See [runtime fields](../reference/plugins.md#runtime-分组字段) and [extension points](../reference/extension-points.md).                                                                                                                                                               |
| Function `value.events`, `value.pluginData`, `value.interactions`, or `value.preGameDone` implicitly cause effects or completion | `value` is the exact business value and can be an object, array, scalar, or `null`. Put writes in `HandlerResult.effects` and completion in `completion`. Internal `RuntimeResult.output`, `effects`, and `completion` are separate; a hook replacing function `output` must update `canonicalValue` too. Inputs, schemas, and `recordAs` share the business value. See [inputs and outputs](../reference/plugins.md#输入和输出).                                                                                                                                                 |
| Extension handlers read snapshot-style cross-plugin `pluginData` or register arbitrary points                                    | Use typed `provideExtension(point, id, handler)` for known points. The host execution scope lazily calls `readPluginData(pluginId, namespace)`; a provider handler uses owner-bound `ctx.pluginData.get/list`. Share across plugins through public services/contracts. Check schema, ordering, timeout, and failure policy. See [extension points](../reference/extension-points.md) and [plugin communication](../reference/plugin-extensions.md).                                                                                                                               |
| Private character mirrors, old Lorebook identity, textual `lastPlayerInput`                                                      | Character schemas/records belong to the kernel World Model; Lorebook identity includes the world/player/plugin owner. `ctx.playerMessage` remains text; `ctx.session.lastPlayerInput` is a structured submission or `null`. Detached jobs need complete `turn-digest@1`, including observed terminal runtime states; recreate old jobs/snapshots. See [World Model](../reference/world-model.md) and [plugin inputs](../reference/plugins.md#输入和输出).                                                                                                                         |
| World `dimensions.time`, plugin-ID data targets, old projected rule IDs                                                          | Move time to a `world.time-definition@1` data source. Use `pluginPolicy.requested`/`recommended` and `contract:<id>` destinations for plugin data. Projected WorldIR rule IDs now use `world-ir-<SHA256(statement.id)>`, preserving the source in `sourceStatementId`; reimport old rules. See [world time](../reference/world-time.md) and [world data](../reference/world-data.md).                                                                                                                                                                                             |
| Secret saves send a full provider map; image generation guesses roles from tags or only checks plugin installation               | `saveSecrets`, `/api/config/keys`, and desktop `covel:keys:save` accept atomic patches: a string sets, `null` deletes, omitted providers remain. Browser localStorage key writes require Web Locks on HTTPS/localhost. Resolve image roles explicitly; `ImagesContext.isAvailable()` is required and generated results carry the actual `target`. Narrative staging depends on `scene-stage@1`. See [SettingsStore](../reference/settings-store.en.md#secret-channel-boundaries), [model slots](../reference/slots.md), and [image generation](../reference/image-generation.md). |

Embedding calls now carry the expected model identity. Even a same-dimension model change is rejected as drift. To switch models intentionally, recreate the development session/index and reingest from source messages where retained. Derived `__kernel:vector` progress is excluded from snapshots, forks, and browser transfer; an old checkpoint cannot be restored directly as a current session. See [vector index and transfer](../reference/transactions.md#vector-index-initialization-and-transfer).

For example, update one provider with `{"openai":"<new-key>"}` or delete it with `{"openai":null}`. Never put real keys in tests, docs, or ordinary settings snapshots. A world time source can use `schema: contract:world.time-definition@1` and `to: contract:world.time-definition@1` as shown in the [world time example](../reference/world-time.md#definition).

Plugin authors can validate a package with `pnpm validate:plugin <path-to-plugin>`, then run relevant package tests and `pnpm e2e:extensions` to check installed third-party behavior; see [plugin testing](plugin-testing.md) for command arguments and environment. Recheck server-projected UI slots, panel data ownership, and media references. Media bytes must be published before metadata becomes visible, and import failure must preserve other sessions' shared bytes. See [UI slots](../reference/ui-panels.md#kernel-ui-slots) and [MediaStore](../reference/media-store.md).

## Verify and roll back

On isolated new data, check the actual storage/media backend from `/api/health`, world/plugin discovery diagnostics, model slots, and keys. Create a world session; complete setup, one turn, a restart/reload, and relevant media rendering. Plugin authors should also inspect output contracts, effects, extensions, detached settle, and browser/desktop recovery. These are upgrade acceptance steps; historical local or live-model tests from the earlier PR do not establish that this installation has passed.

If startup or acceptance fails, stop the new process and restore **the old app version together with its old database, WAL/SHM, media, browser profile, installed packages, and configuration**. Never open the new schema with the old version or overwrite the sole old backup with new data. Keep running the old version if old progress must remain playable until a separately validated migration exists; this version provides neither automatic conversion nor dual reads.
