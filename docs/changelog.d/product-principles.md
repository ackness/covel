### Documentation

- **The product principles are written down.** `docs/internals/design-principles.md` now opens with them: players come first; bundled plugins are demos on equal footing with community plugins, and the framework runs with every plugin removed; a missing plugin or an unused field must not stop the game; one core serves the desktop app, the self-hosted web app and, later, the official web app: the desktop and self-hosted apps are the current focus, the official web app is not supported yet, and the core stays generic so that it can be added without rewriting it; manifests ask only for what cannot be derived or defaulted; and contracts change directly during fast development. `AGENTS.md` summarises them for coding agents.
- **Pages that contradicted the principles or the code are corrected.** "Core plugin" no longer names every bundled plugin: a `kind: core` plugin joins every game by default, and the player can turn it off on the session-prep screen (the tables of `docs/builtin/index.md` say "default-enabled" instead of "always enabled"). The storage and HTTP API pages describe the three deployment forms instead of three tiers and say that the official web app is not supported yet: SQLite is the default, PostgreSQL is for professional developers and special needs, and the two must behave the same. The `commercial` tier is reserved for a possible commercial edition that this repository does not develop, and the Docker stack in `docs/CONTRIBUTING.md` runs a personal `self` instance. `docs/reference/slots.md` no longer says that a manifest `wires` field is still accepted. The pages on the bundled worlds say which play mode each one demonstrates, and that `emberback` is written in English to show a world in several languages. The glossary has "Bundled plugin", "Deployment form" and "Official web app", and the empty page `docs/en/reference/orld-installation.md` is gone.
