### Changed

- **A changelog entry is a file of its own.** A change adds `docs/changelog.d/<slug>.md` with its entries under `### <Section>` headings and no longer edits `docs/CHANGELOG.md`, so two pull requests do not conflict over the changelog. `pnpm changelog:preview` prints the pending `[Unreleased]` section, `pnpm changelog:release <version>` moves the entries into `docs/CHANGELOG.md` at release, and `pnpm check` validates every fragment (`pnpm check:changelog`). A branch opened earlier may still add lines under `[Unreleased]` until the next release; after it `pnpm check` refuses them. Format: `docs/changelog.d/README.md`.
- **The pre-push hook tests what the push changed.** It still installs in a clean checkout and runs `pnpm check` and `pnpm e2e --list`, and now runs the tests of the packages the branch changed since the remote's main branch, with the packages that depend on them and the suites that read the changed files from outside their package; CI runs every suite. A change to the lockfile, `turbo.json`, `vitest.base.ts`, the root `package.json` or `tsconfig.json`, a push to `main` and a pushed tag still run everything, and so does `COVEL_PUSH_CHECK=full git push` or `pnpm check:push --full`. A commit that passed is remembered for 12 hours: a push that is repeated, or one that follows `pnpm check:push`, sends at once.
- **`pnpm release:preflight` fails when `docs/CHANGELOG.md` has no section for the version in `package.json`,** and the release workflow refuses to publish a tag while a changelog fragment is not assembled.
