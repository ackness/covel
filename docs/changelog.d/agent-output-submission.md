### Breaking

- **Every agent now finishes through the `submit-output` tool.** Remove `finishWith`, `completion.require: explicit`, `runtime-done`, `agent.loop.fallback: answer-without-tools` and `truncation: accept`; business `completion.afterTools` prerequisites no longer terminate a runtime. Reply text and the last business result cannot complete an agent. Invalid JSON, schema, story shape and review failures come back as correlated tool errors and are corrected inside ordinary loop steps with independent bounded counters (output repair defaults to three corrections for `story` and `actor` runtimes and one for `system`, review to two, missing business work to one); finalizers offer only submission, so no tools-off repair or lenient invalid-story acceptance remains. Loaded object schemas stay unchanged, with host defaults for schema-less story and system agents. Update agent prompts, `ReviewAgentOutput` registrations, fixtures and HTML session pages, and reload declarations and cached compiled definitions. Recreate suspended development runs and checkpoints written under the previous contract, and re-record exact-match captures, starting with Lantern Barrow. Business contract IDs and compatible committed story history remain valid; no blanket database deletion is required. See [completion](../en/reference/plugins.md#agent-output-submission), [submission](../en/reference/tools.md#submit-output), [stop reasons](../en/reference/protocol.md#stop-reasons), [testing](../en/plugins/testing.md) and [recording](../en/ship/real-model.md#recording-and-replay).

### Added

- **Agents can submit a business tool’s canonical result without copying it.** Declare `io.output.from: { tool: name }`, then call `submit-output` with `{}` after that tool succeeds. The host validates and reviews its latest successful public content, including results restored after suspension. Submission arguments are ignored in this mode, including wrappers, extra fields and malformed JSON; missing work still returns a correlated error. Static installation resolves the package’s own declared contract schemas too. Bundled world time, world facts, world initialization, story planning and action suggestions use this path. See [output sources](../en/reference/plugins.md#agent-output-submission).
- **Final output has a dedicated review hook.** `ReviewAgentOutput` checks validated submissions using public results of the subject runtime's own tools. The hook receives the candidate, the original call identity and the public tool evidence, and can accept or request a bounded correction, without replacing accepted output or creating effects. Effects remain owned by successful business tools; accepting output does not promise persistence. `PostLLMResponse` continues to inspect actual provider responses. See [hooks](../en/reference/hooks.md#reviewagentoutput).
- **Complete stories can opt into segment reveal.** The shared `Reveal` component and template metadata reveal whole blocks within two seconds, so a story that opts in appears block by block instead of all at once, with Show all and a device-local Instant text override. Reduced motion, history, reconnect, reload and view remount are instant. Semantic content and copy/export remain complete. See [Reveal](../en/reference/ui-components.md#complete-content-reveal).
- **Loop profiles expose bounded correction and finalization policy.** `story`, `actor` and `system` share submission validation. Story and actor profiles can request submission when a tool loop repeats; system fails. Steering remains independent of provider streaming. Output repair defaults to three corrections for `story` and `actor` runtimes and one for `system`, so a model that answers in prose and then sends cut-off submission JSON can still finish the turn; each repair returns its error inside the same conversation. Deadline reserve defaults to zero, and enabled finalization offers one submission-only request after required work. See [loop profiles](../en/reference/plugins.md#loop-profile-agentloopprofile).

### Changed

- **Acceptance still precedes persistence.** Output never creates effects merely because it arrives through a tool. Commit receipts and persisted messages determine success; failed commit, cancellation, refusal and rejected candidates publish no story. Resubmission keeps previous business work without repeating writes. Resumes retain the admitted schema, spent steps and correction counters; children use the same gate while keeping their existing privacy and write boundaries. See [flow](../en/internals/flow.md) and [resume](../en/reference/protocol.md#suspend-and-resume).
- **Stage input no longer waits for reading.** Character typing and the final-click gate are removed. Paragraph navigation, rereading and local Auto-play remain independent of action availability and server advancement. Scene Stage opts into the shared segment presentation; instant remains the host default.
