### Fixed

- **A malformed write from an optional plugin no longer fails the whole turn.** A proposal such as a `narrative.append` with no `content`, or a `plugin.data` value with a BigInt or a circular reference, used to make the store write throw on SQLite and PostgreSQL. That rolled back the turn and its story, so every turn of the session failed. The memory backend stored an empty message instead. Every proposal is now checked against the schema of its type before it commits. A malformed one is rejected with the code `proposal-invalid`: the plugin's writes for that turn are dropped and the story is kept. Values are committed as their JSON copy, so all backends store the same thing.
- **A write that refers to a picture the session does not hold is refused at commit.** A `MediaRef` from another session, or one whose file was deleted, was saved into messages and plugin data, and failed only later, when the session was forked (`403` / `409`). Every `MediaRef` in a proposal is now checked against the session when the proposal commits; one that fails rejects the proposal (`media-not-found`, `media-ownership-invalid`, `media-mime-mismatch`). A ref that passes is stored with the stored MIME type and size and without `url`.
