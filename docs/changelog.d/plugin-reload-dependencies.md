### Fixed

- **A development hot reload of a community plugin now picks up changes in the modules its entry, handlers and guards import.** Editing a file such as `lib/helper.js` used to reload the plugin with the old helper until the server restarted. A reload now gives the plugin a fresh module graph: relative ES module imports that resolve inside the plugin directory are evaluated again, while files outside it, `node_modules` packages, `.cjs` and `.node` files stay shared. Production, bundled plugins and the first activation resolve modules as before. Each reload leaves one more copy of the plugin's modules in memory until the server restarts. Rules: `docs/reference/plugin-extensions.md`. Under `pnpm dev` a change to a code file the server has already loaded still restarts the whole backend, because `tsx watch` follows every loaded module; the reload described here is what runs when the server is started without that watcher, and for manifests, UI files and translations.
