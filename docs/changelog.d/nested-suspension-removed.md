### Breaking

- **A nested call can no longer be part of a suspension.** A function handler that received results from `ctx.recursiveCall` and then returns `suspended` now fails with "cannot suspend after a nested call", and nothing it or its children wrote is committed. A function or agent runtime that suspends while running inside `ctx.recursiveCall` fails with "cannot suspend inside a nested call", and its caller receives an ordinary failed result. Top-level suspend and resume are unchanged, and a resumed handler still cannot call `ctx.recursiveCall`. A plugin that suspended after nested calls must ask for input before making them, or split the work into a top-level runtime. Continuations no longer save child results, so recreate development sessions, snapshots and browser checkpoints that hold a pending suspension saved with nested results; committed stories need not be deleted. See [nested calls](../en/reference/plugins.md#nested-calls-ctxrecursivecall) and [suspension and resume](../en/reference/api.md#post-apisessionsidsuspensionssuspensionidresume).
