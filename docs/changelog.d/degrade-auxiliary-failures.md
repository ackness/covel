### Changed

- **A failing dimension provider no longer fails the turn.** When the runtime that publishes `world.dimensions@1` fails, the story still runs and the turn commits and counts. The story reads the saved values frozen when the execution started, the same values the provider republishes, and runtimes that read `world.dimensions@1` run without that input for the turn. The provider's failure shows in the turn's run status and can be retried on its own. The `dimension-snapshot-unavailable` skip reason is gone. Rules: [World Model](../en/reference/world-model.md#turn-timing-and-settlement-receipts).
- **A failing guard hook of an auxiliary plugin costs only that plugin's part of the turn.** In an execution with a story, when a `TurnStart`, `PreRuntime` or `PreStateCommit` handler of a plugin without a story runtime throws, times out or returns an invalid result, it no longer aborts or rolls back the turn: after a `TurnStart` failure that plugin's runtimes are skipped with the reason `hook-failed`; a `PreRuntime` or `PreStateCommit` failure still stops that plugin's own runtime or proposal, and other plugins' runtimes and proposals go on without the handler. A deliberate `abort` or veto works as before. `PreToolUse` and `ReviewAgentOutput` stay fail-closed for every plugin, as do hooks of the framework and of the story plugin, and every hook in an execution without a story. The failure still counts toward the fault latch. Rules: [Hooks](../en/reference/hooks.md#auxiliary-hook-failures).
