### Breaking

- **Pending development work needs current read evidence.** Cancel or recreate unresolved suspensions, pending or retryable runtime jobs, and checkpoints or snapshots containing previous pending proposals. A stale derived replacement is refused at commit with `conflict`; an explicit retry recomputes it from current reads. Committed values, characters and completed sessions need no database reset or migration.

### Added

- **The host guards read-derived replacements against stale same-key data.** Explicit reads capture private content baselines (absence included); own data injected through `io.selfData` counts as reads when the agent holds write tools for that namespace, using the full stored values before model projection or summary truncation. Checks run at the serialized transaction mutation boundary and survive suspension and resume. A derived `merge`, `upsertItem` or delete, or a derived `merge` list that surrounds an `inc`, whose baseline went stale is rejected with `conflict`; pure relative lists and blind writes keep their semantics, and cross-key and phantom protection are excluded. An auxiliary conflict discards its unit; a failed story-attached operation preserves the story text and unrelated operations; malformed auxiliary payloads fail ordinary proposal validation and preserve valid story text. Retries are explicit and conflicts do not count toward a plugin's fault latch. Payload fields cannot override the host's target identity, hooks cannot erase or redirect guards (vetoing a guarded prefix rolls back the batch and its success notifications), and accepted sub-agent reads through inherited world views contribute character baselines to the caller while failed or cancelled children discard them.
