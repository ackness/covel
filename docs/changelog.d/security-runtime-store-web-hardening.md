### Breaking

- **Encrypted `SecretVault` now uses per-file salted `scrypt` and rejects plaintext downgrade files.** When `COVEL_CREDENTIALS_KEY` is configured, `SecretVault` derives keys with per-file random-salt `scrypt` (AES-256-GCM with strict 12-byte IV and 16-byte tag checks) and refuses to read older `SHA-256` or unencrypted (`encrypted: false`) files on disk. Re-save plugin credentials under `<config>/secrets/` if migrating an existing development directory ([env-registry](../en/reference/env-registry.md)).
- **`exec.localBridge` is locked as a reserved capability.** Policy overrides (`PUT /api/permissions/policy` / `COVEL_PERMISSIONS_POLICY`) and persistent plugin grants targeting `exec.localBridge` are rejected until a local subprocess executor exists ([security](../en/internals/security.md#instance-policy-and-persistent-grants)).

### Changed

- **Tightened author-facing manifest schemas and regenerated JSON Schema artifacts.** `contributes.data` validates plugin namespace keys; runtime `io.inputs` keys, JSON Pointers, schema references, `recordAs` names, and `agent.completion.afterTools` entries reject malformed or blank inputs; and `plugin-manifest.schema.json` enforces `minProperties: 1` on `contributes.worldProjections` and its `outputs`.

### Security

- **Enforced capability governance uniformly across runtimes, routes, and trust boundaries.** Closed `plugin.communityCode: "operator-only"` bypasses on shared hosts, enforced `plugin.declarative` L1–L3 policy across execution and fork paths, wired live `net.httpDeclared` checks into function/presentation runtimes and provider `context.http` helpers (in both the server and `@covel/test-runtime`), and activated real enforcement for `plugin.globalAutoEnable`, `session.bridgeWrite`, and `runtime.highRiskTools` ([security](../en/internals/security.md#instance-policy-and-persistent-grants)).
- **Hardened outbound HTTP, wire isolation, provider sources, sandbox workers, diagnostics redaction, and ZIP extraction.** `fetchWithAuthProxyRetry` enforces strict direct DNS pinning on fallback; `provider.source@1` validates RFC 9110 headers and invalidates caches on permission changes; media wires enforce plugin ownership matching text wires; `sandbox-worker` strips host `env`/`execArgv` with concurrency and payload caps; `POST /api/ai/models` and `POST /api/ai/ping` gate diagnostics behind `server.diagnostics`; and ZIP extraction enforces cumulative uncompressed size, expansion ratio, and collection budgets mid-stream.
- **Hardened rate limiting, request body draining, loopback OAuth callbacks, plugin instance routes, session/media endpoints, and plugin uninstall cleanup.** `X-Forwarded-For` is parsed right-to-left skipping `TRUSTED_PROXY_IPS`; unread body draining streams with O(1) memory bounded to the route's own limit; loopback callback listeners enforce loopback `Host` headers, `Content-Security-Policy: default-src 'none'; frame-ancestors 'none'`, `X-Frame-Options: DENY`, `::1` collision checks, and disconnect cleanup; instance app-action and config-flow routes activate only the target plugin, set `Cache-Control: no-store` on flows, and enforce a 30s action timeout; `POST /api/sessions/:id/resume` redacts concealed runtimes; `HookPipeline` runs `runsFor` before `match`; `/api/ui-specs?sessionId=` verifies session incarnations; `PUT /api/sessions/:id/plugins/:pluginId` rejects ended/deleting sessions; `POST /api/sessions/:id/steer`, `messages/sync`, `runtime-outputs`, `interaction-records`, and `/api/media` enforce authentication, payload, and pagination bounds; and uninstalling a community plugin purges its schedules, flows, provider-source cache, session approvals, secrets, instance data, and persistent grants ([api](../en/reference/api.md)).
- **Bounded local model relay resources and unblocked graceful shutdown.** Added per-IP channel limits (`4`), body idle timeouts (`60s`), byte-bounded buffering (`4 MiB` per request / `64 MiB` total), and abort-aware SSE heartbeats ([security](../en/internals/security.md#local-model-relay)).
- **Plugin webview `src` URLs and `webview.entry` paths fail closed.** Sandboxed plugin webviews reject non-`/plugin-assets/` paths, protocol-relative URLs, path traversal segments, and control characters before probing or connecting, and `pluginUiSpecSchema` / `pluginUiSpecIssues` validate `webview.entry` path safety even when `webview.root` is omitted.
