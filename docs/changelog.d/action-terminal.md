### Fixed

- **Stop works before a turn starts and between the setup turn and the opening.** A stop pressed while the action waited for the session or for the previous turn's memory update used to answer "no turn in progress"; one pressed after setup was saved answered OK and the opening still ran. A stop now applies to the player's whole action: an action that has not started does not start and saves nothing, and an opening that has not started does not start. The stopped opening shows as stopped and can be retried, and it then runs as the opening. Once an action has nothing left to stop, `POST /api/sessions/:id/abort` returns `409`.
- **A saved turn no longer ends in an error when its debug record fails.** If writing the `turn.completed` trace (or announcing background jobs) failed after the turn was saved, the stream ended with `error.occurred` and the opening was skipped. These steps are now only logged: the stream ends with `execution.completed`, and the opening runs.
- **A resent message whose turn is already saved is refused at once.** It used to run the whole turn, model calls included, before the commit refused it. It now ends with `error.occurred` and the code `input_already_committed`, before any model call.
- **A stale retry says what happened.** Retrying a task whose turn has moved on, or recovering a turn that can no longer be recovered, showed "Internal server error" in production. The stream now gives the reason with a code (`retry_source_stale`, `retry_target_not_failed`, `recovery_unavailable`, …), and the app asks the player to refresh the task statuses. Codes: `docs/reference/api.md`.
