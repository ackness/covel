### Changed

- **Four reads no longer grow with the length of a session.** An automatic snapshot takes the last ID and the compaction tags of the model history instead of reading every message with its text. A runtime that writes several characters in one turn reads the character list once for the batch instead of once per character; the name and alias check runs against the batch's own earlier writes, as before. `POST /api/sessions/:id/messages/sync` looks up only the IDs in the request instead of reading every message of the session. The local media store reads and writes picture files without blocking the server, so a multi-megabyte picture attached to a story call or uploaded by one session no longer pauses the streams of the others. `DataStore` gains `listCompactedTurnMessageTags` and `listExistingMessageIds`; a custom backend must implement both.
- **`GET /api/sessions/:id/messages` and `GET /api/sessions/:id/state` are rate-limited** like the paged reads: 120 requests a minute per client and path, then `429` with `code: "rate_limit_exceeded"`. See `docs/reference/api.md`.
