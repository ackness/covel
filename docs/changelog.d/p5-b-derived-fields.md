### Breaking

- **A runtime no longer writes `type`.** A runtime with a `function` block is a function runtime; one without is an agent. Delete `type: agent` and `type: function`; a function runtime that sets nothing else writes `function: {}`. `function.handler` defaults to `./handler.js` next to the manifest; a function runtime with neither a written handler nor that file does not run, and `pnpm validate:plugin` and installation report it. An installed package that still writes `type` loads with the field left out and a warning, and `pnpm validate:plugin` reports it as an error. Rules: "Two kinds of runtime" in `docs/en/reference/plugins.md`.
- **The root `optional` list is gone.** A contract that a runtime reads through `io.inputs` or `schedule.needs` but that `requires` does not list is optional: it binds when a provider is active, and a required input without a provider keeps the runtime from running. Delete `optional:`; a package that still writes it loads with the field left out and a warning, and `pnpm validate:plugin` reports it. `GET /api/plugins/:id` still returns `optional`, now worked out from the runtimes.
- **`contributes.data.*.authoring.source.kind` is gone.** The format comes from `path`: `.yaml`/`.yml`, `.json`, or a media directory without an extension. Delete `kind`, and `key: id` (`key: filename` for a media directory), which is the default. A package that still writes `kind` loads with the field left out and a warning.
- **`package.json` is optional, and its `version` is not read.** The version lives only in `PLUGIN.md`; the check that the two versions match is gone, and the install preview and update check read `PLUGIN.md`. A package without `package.json` loads its `.js` files as ES modules; one that has a `package.json` still declares `"type": "module"`. An installed package keeps working; delete `version` from its `package.json`.
- **The installer names a package that writes no `id` after its folder.** The ID is the written `id`, else the top-level folder of the ZIP, the selected repository folder or the repository name, else the `package.json` name without its scope and `plugin-` prefix. A `package.json` name no longer has to match the written `id`. Order: `docs/en/reference/plugin-installation.md`.
- **Every bundled plugin has a new version.** Setup runtimes of existing development sessions run again at the next player action; recreate a session if its setup guard does not skip work already done.

### Changed

- **The loader works out the fields an author used to repeat.** `id` is the directory name, `kind` is `plugin`, `entry` is `./server/index.js` when that file exists, `provides` takes in every runtime's `io.output.contract`, and the `ui:*` and `cost:*` tags come from the package's panels, actions and runtimes (a written one is ignored; authors write only tags such as `mode:*`). A written `id` must still equal the directory name. `pnpm validate:plugin` warns about a written value equal to the worked-out one. A plugin can now be one `PLUGIN.md` with a description, a stage and a prompt. Table: "Defaults" in `docs/en/reference/plugins.md`.
- **The default scaffold writes no `package.json`, and bundled manifests drop the derived fields.** `pnpm create-plugin` writes `version: "0.1.0"` in `PLUGIN.md` only; `--with-tools` keeps a workspace `package.json` without `version`. The guides `first-plugin.md` and `prompt-only.md` start from the one-file plugin.
