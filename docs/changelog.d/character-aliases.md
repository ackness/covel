### Breaking

- **The `characters` table has an `aliases` column; an earlier SQLite or PostgreSQL database must be recreated.** The server creates tables and never alters one, so a database created before this change opens without a message and then fails every character read and write with `no such column: aliases` (SQLite) or `column "aliases" does not exist` (PostgreSQL). Stop the server, back up the database file with its `-wal` and `-shm` files, and start with a new file (`<covelHome>/data/covel.db` for the desktop app, `./data/covel.db` for a development server without a Covel home); for PostgreSQL recreate the schema. Browser-private saves need nothing: their characters have no aliases.
- **`update-character` reports a miss with other words.** The error is now `Character "<what was passed>" not found. Closest known names: …` (or `Characters in session: …`), not `Character <id> not found in session. …`. A plugin or test that matched the old sentence must match `not found`.
- **A world whose characters share a name or alias does not validate.** In `characters/characters.json`, an `aliases` entry that equals another character's name or alias, or a name that equals another character's alias (letter case, width, spacing and the middle dot do not count), is an error of `pnpm validate:world` at the later record, and a session of such a world is not created. A generated world stored before this change whose character cards repeat an alias across characters fails the same way: edit the alias or generate the world again.
- **`affinity`, `npc-graph` and `codex` key a session character's record by the character's name.** A change addressed by an alias of a session character now goes to the record under the character's name. A development session that already has a second record under the alias keeps it; it is no longer written to.

### Added

- **A wrong alias can be taken away.** `update-character` and `sync-characters.updates[]` accept `removeAliases`, and a `character.upsert` proposal with `expectedVersion` reads the same field. Names are compared as everywhere else (case, width, spacing); a name that is not an alias of the character changes nothing, and the character's own name stays. An alias-conflict error now says that the other character's alias can be removed when it is wrong. There is no editor for it in the app.
- **A character has aliases, and one rule turns a name into a character.** A story calls one person many things; the models that track characters, relationships and affinity looked a person up by one exact name, and a miss made a second character, a relationship on the wrong one or a lost update. A character of the World Model now has `aliases` (ordered, as shown). A world author writes them in `characters/characters.json`; the bundled worlds carry the ones their character cards already listed. A model adds one through `aliases` of `update-character` / `sync-characters` when the story reveals a name, and `create-character` takes them too. `resolveCharacter` in `@covel/plugin-handlers-utils` is the one lookup: exact ID, then name, then alias, compared without regard to letter case, full and half width, spacing, surrounding quotation marks, the middle dot of a transliterated name, the kind of apostrophe and a leading "the"; titles and honorifics are not removed, and there is no fuzzy match. A name that two characters have is reported as ambiguous. An alias that belongs to another character is refused, by the tools and again at commit, with that character named. `update-character` accepts the id, the name or an alias; a miss names the closest known characters. `create-character` returns the existing character for a name that is an alias. `get-character` and `list-characters` show aliases. `affinity`, `npc-graph`, `codex`, `scene-stage` and `world-ir` resolve names through it, and the character panel shows aliases (read-only). In prompts a name with aliases reads `Name (aka a, b)`: 5 to 9 tokens per character on the bundled worlds. See `docs/reference/world-model.md`.
