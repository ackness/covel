### Breaking

- **The settings of an agent sit directly under `agent`.** `agent.loop.completion` moves to `agent.completion`, `agent.llm.toolChoice` to `agent.toolChoice`, and `agent.llm.reasoningEffort: disabled` becomes `agent.reasoning: false`; `agent.llm` is gone and `agent.loop` keeps only the time, retry and step limits. Move the three fields up one level. Rules: "Completion conditions" and "Tool choice and reasoning" in `docs/en/reference/plugins.md`.
- **`schedule.completion` is now `schedule.detached`.** Write `detached: true` in place of `completion: { mode: detached }`, and `detached: { settle: true, maxSettleWaitMs: … }` in place of `settle: before-next-execution`; `maxQueueMs` and `maxExecutionMs` stay. `overlap` and `stalePolicy` are gone: each had one allowed value, and detached jobs of a runtime still run one at a time and a stale job is still rejected. `GET /api/plugins` and `GET /api/plugins/:id` return `turnCompletion.settle` as a boolean and no longer return `overlap` or `stalePolicy`. Jobs already queued keep working.
- **`schedule.manual.execution` is now `schedule.background`.** Write `background: true` in place of `manual: { execution: background }`, and delete `manual: { execution: sync }`.
- **A manifest that still writes a removed nested field does not load.** `agent.llm`, `agent.loop.completion`, `schedule.completion` and `schedule.manual` are unknown keys inside fields the host reads, so loading, installation and `pnpm validate:plugin` reject the manifest and name the file and field.
- **Every bundled plugin whose manifest changed has a new version** (affinity, branch-reply, char-creator, character-blueprint, chat-mode-narrator, codex, dice-check, guide, history-compaction, memory, narrator, npc-graph, scene-stage, soundtrack, story-events, world-init, world-ir, world-time). Setup runtimes of existing development sessions run again at the next player action; recreate a session if its setup guard does not skip work already done. `guide` and `world-ir` now ask the model to call a tool on every step instead of naming their one tool, which is the only tool each of them sees.

### Added

- **`agent.finishWith: <tool>` ends an agent after one tool.** The run completes once that tool succeeds and fails without it, and the model must call a tool on every step unless `agent.toolChoice` says otherwise. It replaces `completion: { require: tool-use, afterTools: [<tool>] }` with `toolChoice: required`; the full `completion` stays for several tools or `runtime-done`, and the two cannot be written together.
- **Hooks and extensions have a one-line form.** `contributes.hooks: [PreToolUse]` lists hook events by name, and `contributes.extensions: [prompt.segment@1/notes]` writes an extension as `<point>/<id>`. The object form stays for `enforce`, `order`, `slot`, `watch` and `preview`.
- **`pnpm validate:plugin` warns about more fields written with their default or in a long form.** New defaults: `schedule.detached: false`, `schedule.detached.settle: false`, `schedule.background: false`, `agent.reasoning: true`, `agent.toolChoice: required` beside `finishWith`, and `contributes.extensions[].order: 0`. A hook with only `event`, an extension with only `point` and `id`, and the long form of `finishWith` each get a warning that names the shorter form. Table: "Defaults" in `docs/en/reference/plugins.md`.

### Documentation

- **Fields no bundled plugin uses moved to an advanced part.** `covel`, `homepage`, `author.about`, `author.links`, `contributes.wires`, `events[].advertise`, `prompt[].position.depth`, `commands[].context`, `arguments[].variadic` and `choices`, the settings controls `text`, `textarea`, `integer`, `slider` and `slot`, and the agent loop fields `maxSteps`, `firstTokenTimeoutMs`, `idleTimeoutMs`, `loopDetection` and `maxRecursionDepth` are listed in "Advanced fields" of `docs/en/reference/plugins.md` and "Rarely needed fields" of `docs/en/plugins/advanced.md`. They all still work.
