### Added

- **`pnpm validate:world` checks the character attributes that plugin data names.** A plugin declares in `contributes.data.<namespace>.authoring.references` which values of its records are the `id` of an attribute of the world's `characterSchema` (`path`, `to: character-attribute`, optional `type` and `within`). A value that names no attribute, one of the wrong type, or a number outside the attribute's `min` and `max` is an `attribute-reference` error with the file and the place in it. `tabletop-rules` declares it for its point-buy rules, so a mistyped attribute `id` in `data/tabletop-rules.json` no longer waits until a session starts to fail. Rules: `docs/reference/plugins.md`, `docs/reference/world-data.md`.
- **`pnpm validate:world` warns about a field that no model reads.** A field of a world-data record or a character whose name ends in `At` or is `timestamp`, with an ISO time as its value, is left out of what a model reads as bookkeeping. Each one now gives a `model-hidden-field` warning that names the file, the record and the field. Rename a date of the story (`date`, `diedOn`) or write it in another form to keep it visible. An `id`, or a field whose name ends in `Id` / `Ids`, that holds a UUID is left out the same way and gets the same warning, with the hint to use a readable ID such as `npc-lin-yao`.
