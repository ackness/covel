### Breaking

- **A world has one character file.** The roleplay notes of a character (persona, voice, secrets, rules, example lines, relationships) are written in its record in `characters/characters.json`, under `blueprint`, and no longer in a separate `characters/main-cast.json`. The notes do not repeat the record's name, aliases, description, type or fields: a `name` or similar field in `blueprint` fails `pnpm validate:world`. Relationship keys are character ids (`npc-su-yao`, not `su-yao`). `main-cast.json` is no longer read; move each card's notes into the record of its character. The four bundled worlds are converted. Rules: `docs/reference/world-data.md#one-character-file-per-world`.
- **Character Profiles matches a character by its id only.** `character-blueprint` (0.0.37) stores the notes keyed by the character's id and no longer matches `npc-<card id>`, for the notes and for portraits alike. The read-only "Preset Characters" panel is gone: the characters are in the character list. Development sessions of Emberback, Haruka Academy, Lantern Barrow and Mistport created before this change keep the old notes keyed by card id, which the narrative no longer reads; recreate them.
- **The world generator writes characters as character records.** A generated character has `id`, `name`, `type`, `description`, `aliases` and `fields`; `attributes`, `role`, `instantiate`, `schemaVersion` and loose persona fields are dropped. Roleplay notes, when requested, go into each character's `blueprint`.

### Added

- **A plugin can take its data from the world's character records.** `contributes.data.<namespace>.authoring.characterField` names a field of a character record (in place of `source`); the kernel imports the record as a character either way and gives that field to the active plugins that accept the contract, keyed by the character's id. Without such a plugin the field is ignored. `pnpm validate:world` checks the field against the receiver's schema, warns when no plugin reads it or a new session does not enable one, and locale files translate it like the rest of the record. `pnpm describe:authoring` and `GET /api/framework/authoring` report `characterField`. Reference: `docs/reference/plugins.md`.
- **A world kept in a store imports its characters like a package.** `metadata.embeddedCharacters` goes through the same import as `characters/characters.json`, so plugin fields in those records reach their plugins and the import ledger records each character.
