### Added

- **Declared datasets are enforced at commit.** Every plugin-data write into a `contributes.datasets` namespace is checked against the dataset's `ops` (a whole-value write counts as `set`, a delete as `delete`) and its record schema; a violation, or a missing schema document, is rejected with `code: "dataset-violation"`. The rules cover function `ctx.pluginData` writes, `plugin.data` proposals, plugin action and command RPC writes, world imports and syncs, including packages without runtimes; prepared imports keep captured schemas and validate final media records and UTF-8 JSON size before persistence. World seeding and replacement require `set` and true managed removals require `delete`; replacements use the physical plugin, namespace and key, so changing a source target URI (including toggling `+lorebook`) does not require `delete`. `force` cannot bypass the rules, and management plugin-data PUT and DELETE remain authorized operator overrides. RPC writes stay immediate per call: refused records stay unchanged and earlier successful calls remain persisted. Invalid optional projection outputs are deferred as a whole, preserving older managed records, and Inventory and Affinity permit removal of world-seeded records. Existing data is not scanned or rewritten. See `docs/reference/plugins.md` (Datasets).
