### Fixed

- **Hardened runtime execution, retry fallback, subagent isolation, hook confinement, and suspension resume.** `streamLLMWithRetry` resets streaming/TTFB/idle timers cleanly on `stream-reset` and `onQueueStart`, `ctx.agents.run` forks world/plugin-data visibility and operations and commits only on success, `TurnStart`-confined plugins no longer enqueue detached or background jobs, `PostToolUse` stringifies replacement results while pinning `toolCallId`/`name`, function-runtime suspensions preserve prior `toolCalls` and `emittedEvents` across resume, and rollback paths immediately discard staged per-request credentials while `settled-session-lock` supplies credentials to newly arrived unrunnable jobs.
- **Fixed one-time (`scope: "once"`) community event RPC approvals and instance-scoped plugin hot-reload.** Event dispatch checks grants non-destructively during preflight and consumes one-time grants atomically under `sessionLock` (avoiding spurious `409 approval_scope_changed` loops and premature consumption); hot-reloading an approved community instance-scoped plugin now preserves its registrations and refreshes scope metadata.
- **Fixed server lifecycle, startup ordering, graceful shutdown, scheduler, config flows, and memory leaks.** `ai.setProviderSourceResolver` is bound before `onStartup`/`AppStarted`/background workers start, startup failures and shutdown clean up every owned resource independently, `graceful-shutdown` always drains before exiting and closes idle connections first, `world-file-watcher` attaches `error` listeners, `AppEventDispatcher` races handlers against timeout and enforces `plugin.instanceScope` for builtins too, `AppScheduler` separates one-shot and recurring timers and aborts/fences stale runs on reload, `ConfigFlowEngine` reserves concurrency slots before async `start()` and cleans up rollback/loopback state, and `pluginEntries.clearSession`, `eventDirectory.warnedConflicts`, and `browserWorkspaceCache` are bounded/cleaned up.

### Security

- **Hardened loopback OAuth callbacks, plugin instance routes, and session/media API boundaries.** Loopback callback listeners enforce loopback `Host` headers, set `Content-Security-Policy: default-src 'none'; frame-ancestors 'none'` and `X-Frame-Options: DENY`, skip `::1` port collisions, and settle/close on early client disconnect; instance app-action and config-flow routes activate only the target plugin, set `Cache-Control: no-store` on flows, and enforce a 30s server-side timeout on app actions; `/api/ui-specs?sessionId=` verifies the session incarnation barrier; `PUT /api/sessions/:id/plugins/:pluginId` rejects ended/deleting sessions before queuing approvals; `POST /api/sessions/:id/steer` authenticates before body validation and caps message length; `POST /api/sessions/:id/messages/sync` bounds batch size, content length, and timestamps; `GET /api/sessions/:id/runtime-outputs` and `interaction-records` clamp `?limit=` to 500; and `POST /api/media` returns `413` over 20 MB while `POST /api/media/cleanup` rejects malformed JSON ([api](../en/reference/api.md)).
