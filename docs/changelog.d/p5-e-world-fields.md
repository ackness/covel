### Breaking

- **A world's `pluginPolicy` is one built-in pack plus a few plugins.** Write `preset` (a pack of `packs/builtin.yaml`), `plus` (the plugins the world also wants), and optionally `pitch` (the `label`, `description` and `reason` the session-prep screen shows for that pack), `packs` (the IDs of the packs the player may pick) and `requires`. `presetId`, `requested`, `recommended`, `preferredTags` and `avoidedTags` are ignored with a `manifest-unknown-field` warning, and `packs` written as objects (packs a world defined itself) make the whole `pluginPolicy` invalid, so such a world starts with no plugin selection. Rewrite the policy of every world you wrote; worlds in `COVEL_USER_WORLDS_DIR` made by an earlier AI world creation must be generated again or edited by hand. `kind: core` plugins are never listed: every session has them. Reference: `docs/reference/world-data.md`.
- **The languages of a world come from its files.** `supportedLocales` is no longer a field of `world.yaml`: a world has an edition in each language that has a `world.<locale>.yaml` or a `WORLD.<locale>.md` at its root, plus `defaultLocale`. Delete the field. A `world.<locale>.yaml` or `WORLD.<locale>.md` now makes an edition even when the field did not list its language.
- **`dimensionSources` is removed.** Declare dimensions inline in `world.yaml` or as the whole table in `data/dimensions.yaml`.
- **A descriptor only writes what differs from the conventions.** Every world package is read by convention, with or without `data/world.data.yaml`. An entry whose `path` is a conventional source's path changes only the fields it writes (`enabled: false` turns the source off); any other entry adds a source. A descriptor that listed every conventional file still loads, but a conventional file it left out is now imported: turn it off with `enabled: false`, and delete the entries that repeat the conventions. Conventional sources have new IDs (for example `blueprints` instead of `cast`, `rules-campus-life` instead of `campusRules`), so an override descriptor that names a source of a bundled world must use the new ID, and sessions of the bundled worlds created before this change should be created again.

### Added

- **The smallest world is `name`, `summary`, `defaultLocale` and `WORLD.md`.** `id` is optional: a world takes the name of its folder, or of its ZIP file when installed from one. `docs/worlds/first-world.md` starts from this world.
- **Rule files go in `data/rules/*.yaml`.** A plugin's `authoring.source.path` can end in `*.<extension>`: each such file of the folder is a conventional source, imported in file-name order, so a world adds a set of rules by adding a file.
- **`pnpm validate:world` reports values that need not be written.** A `default-value` warning names a `characterSchema.types` equal to the default `[npc, companion]` and a `kind: core` plugin in `pluginPolicy.plus`; `unknown-pack`, `preset-not-offered` and `pitch-without-preset` check the new policy fields.
