### Fixed

- **A failed parent handler no longer commits its `ctx.recursiveCall` writes.** A nested call's writes now commit only when the handler that made it succeeds and no PostRuntime Hook changed its status, the same rule as the handler's own writes. A parent that throws, times out or returns `failed` or `skipped` discards them, at every nesting level. A parent that suspends for input keeps its own writes for the resume but discards its nested calls' writes; they are not yet saved with the suspension. An agent guard's nested call commits only when the guard skips the run. See `docs/reference/plugins.md` (Nested calls).
- **A runtime and its nested calls commit as one unit.** Next to a successful story, a non-story runtime's own writes and those of every nested call below it share one savepoint: a rejected write anywhere in it discards all of them, and runtimes that depend on that top-level runtime follow the existing dependency rules. A unit that holds a story or setup run, even a nested one, follows the story rule, so a rejected write in it rolls back the execution. Nested results commit before their parent. See `docs/reference/transactions.md`.
- **A suspension inside a discarded unit is never saved.** It cannot be resumed later and does not replace a suspension that still stands. When the execution leaves no other suspension, its turn ends as if the suspension had been abandoned: the turn counts and the held-back detached jobs are queued. A suspension that is saved holds back its detached jobs settled for what the commit dropped: a job that hard-depends on a dropped runtime is removed, and the rest see it as failed.
- **`ctx.recursiveCall` returns a copy.** Changing the returned nested result no longer changes what commits or which plugin owns the writes.
- **Dropped runs are settled per run.** When the same runtime ran nested and at top level, `isolatedRuntimes` entries, saved `turn_results` entries, conversation messages and trigger counts now follow the run that was dropped (`isolatedRuntimes` entries carry its `runId`) instead of every run with that runtime ID. The action stream's commit-time `runtime.failed` corrections now also cover dropped nested runs and carry `runId` and `turnId`; a dropped nested run is not reported while a top-level run of the same runtime committed. See `docs/reference/protocol.md`.
