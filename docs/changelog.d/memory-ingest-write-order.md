### Breaking

- **Data schema version 5: an earlier SQLite or PostgreSQL database is refused at startup.** `turn_messages` has a new `write_seq` column, and the new `session_write_counters` and `record_changes` tables are filled by triggers. A database recorded at data schema 4 stops the server at startup with `StoreSchemaVersionError` ("written by an older Covel (data schema 4; this version uses 5)"), before any table is created or changed; one from before the version was recorded is refused for the missing `turn_messages.write_seq` column. Back up the SQLite file with its `-wal` and `-shm` files and start with a new data directory or `SQLITE_PATH`, or point `DATABASE_URL` at a new, empty PostgreSQL database. Browser-private saves need nothing. See `docs/internals/storage.md`.
- **`readTurnMessages` cursors are save positions.** A cursor a plugin stored from an earlier version is rejected with `Invalid turn message cursor`; read from the start again (`after` omitted). Pages now come in the order messages were saved, which is the time order except for background output saved after a later turn.
- **Store contract changes for a custom `DataStore`.** `listTurnMessagesAfter(sessionId, after, limit)` takes the last `writeSeq` read (or `null`) and returns messages with their `writeSeq`. New: `listRecordChanges` (the change feed of lorebook entries, characters and plugin data, deletions included), `getCharacter`, and on the vector capability `getVectorPayloads`.

### Fixed

- **Semantic recall no longer loses a message saved late.** The recall index moved along message timestamps, so a background execution's message, saved after a later turn had been indexed, was never embedded. It now moves along the order messages were saved; a plugin's `readTurnMessages` had the same gap and is fixed with it (F-025).
- **Archival memory no longer rereads the whole corpus every turn.** After each turn the archival index read every character, lorebook entry and searchable plugin data record and rewrote a hash of all of them; a semantic archival search read them all again. It now reads only the records changed since its last position (deletions are kept as tombstones), skips embedding when the stored vector already has the same text, and a search reads only the records its hits name (F-039).
