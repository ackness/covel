### Breaking

- **Player input is one action type, `submit_actions`.** `POST /api/actions` no longer accepts `send_message`, `execute_command` or `submit_interaction`. A client sends `{ type: "submit_actions", payload: { actions: [...] } }`: a message is `{ kind: "say", text }`, a slash command `{ kind: "command", text: "/..." }`, and a form, choice or confirmation answer `{ kind, interaction: { turnId, interactionId, type }, fields }`. The server checks each action against the seat's role and fills in the seat (the primary seat) and the acting character (the seat's current character). A failed turn is retried as `submit_actions` with the resolved actions; one that answered an interaction is retried as `retry_turn`. External clients must switch to the new action; no stored data needs to be recreated. Contract: `docs/reference/api.md`.

### Added

- **Plugins can declare their own action kinds.** `contributes.actionKinds` names a kind, the seat roles that may submit it, whether it carries text or an actor, a JSON Schema for its `fields` and its composer label. The wire kind is `<pluginId>/<name>`. Contract: `docs/reference/plugins.md`.
- **`GET /api/sessions/:id/action-kinds` lists the kinds a session accepts** (the base kinds `say`, `act`, `narrate`, `direct`, `advance`, `command` plus the active plugins' kinds) and the kinds each seat may submit now.
- **Function runtimes read the player's actions.** `ctx.playerActions` holds the resolved actions of the turn (empty without player input); the `TurnStart` hook payload and the `turn-digest@1` input carry them as `actions`. `ctx.playerMessage` stays, now the kernel's rendering of the actions: a single player's message keeps its text unchanged, while a second character, a host or a plugin kind is named in it (`[Scout · says] ...`). Plugins that read `playerMessage` (memory, NPC graph retrieval, scene cast) see the labelled text in such sessions.
- **A player's chat message keeps the actions it carried.** `Message.actions` on the message API holds the resolved actions (an action's `fields` over 4 KB are left out); `content` stays the raw text.
