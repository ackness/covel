### Fixed

- **A form answered late in a tool loop reaches the model where it was asked.** An endpoint that returns no tool-call ID (Gemini models often, some OpenAI-compatible relays) got `call_<position>`, so every step of a loop had a `call_0`, and resuming a runtime that suspended at a later step overwrote an earlier step's tool result with the player's answer. A missing ID is now a digest of the request and the call's position: different in every step and every runtime, and the same when a recorded session is replayed. Resume replaces the last result under the suspended ID.
- **Gemini: function responses are a content of their own.** Text that follows tool results (a player message, a correction hint, a late system instruction) is the next `user` content, as it was before late system messages stayed in place and as the AI SDK's Google provider sends it. Only plain text neighbours merge. Neither shape has been checked against Google's endpoint; `lateSystemAsUser = false` still restores the earlier request.
- **A 400 from a Responses endpoint is read with a size limit.** The check for a model that refuses encrypted reasoning read the whole error body without one.
- **A form answer is held to the length of a player's message** (100,000 characters). A longer text field is refused under its own field, and fields that make a longer message together are refused for the form as a whole. Before, the turn after such an answer could fail and its retry was refused.
- **A form validator that throws no longer shows its error text to the player.** The submission fails with `form_validator_failed` and a fixed text; the plugin's error is in the server log.
