# SettingsStore 与模型设置

> [English version](./settings-store.en.md)

`@covel/settings` 提供 schema 注册、内存值、订阅与持久化。Web 使用 localStorage；桌面通过配置 API 使用 `settings.json`。API key 使用独立的 secrets 通道。

## Schema 归一化

已注册的非密钥设置使用 schema 的解析结果作为可见值，包括加载、动态注册、`set()`、导入、刷新和写入失败后的回滚。嵌套 `.default()` 和字符串修整会体现在 `get()`、导出及订阅通知中；显式写入会保存解析结果。未注册的键保留原始值。

加载或刷新时补齐默认值不会单独触发保存。revision 冲突检测仍比较后端确认的原始快照，避免把补齐默认值当作远端修改。设置 schema 必须接受自身持久化后的输出，且归一化应当幂等，以便重载、重复注册和同步。

旧模型角色绑定同时包含 `modelRef` 和 `presetId` 时，归一化保留 `modelRef`，与路由选择优先级一致。仅包含 `presetId` 的旧绑定继续兼容。

设置备份中的无效自定义主题会被逐条跳过，合法主题继续加载。模型配置导入会过滤旧版条目中类型错误的连接字段，保留同批合法的旧版和新版配置。

设置的数据导入预览使用当前注册的 schema 检查每个条目，不兼容条目和误放在普通 `entries` 中的密钥不能勾选导入；未注册的普通键仍可保留。仅包含独立 `keys` 的备份也可以导入。导入或重置只有在持久化成功后提示完成，保存失败时保留导入预览并显示错误。

## 多实例写入与同步

支持 `loadWithRevision` / `saveWithRevision` 的后端必须检查单调 revision。每次本地修改记录明确的目标键、捕获的目标值及最后确认的基值，并按顺序持久化；相邻两次 `set` 值相同也不能被视为已经保存。

- revision 冲突后，先读取并验证远端快照，再比较本次修改涉及的键。远端仍等于修改前的值，或已等于拟保存值，才可在新 revision 下重试。
- 不同设置键可以安全重放。对象、数组整体视为一个设置键，不隐式合并其子字段。删除和键不存在参与比较。
- 只有前序本地写入成功，才推进已排队同键修改的基值。普通 I/O 失败不被当作远端修改，后续最新意图仍可从确认基值尝试保存；远端同键冲突不会让后续同值调用伪成功。
- 确认快照、排队目标和公开内存彼此隔离。可修改 `get()` 返回的对象后调用 `set()`；调用后再修改该对象，不会改变已排队目标，需要再次 `set()`。
- 同键冲突拒绝当前修改，抛出 `SettingsRevisionConflictError`；`conflictingKeys` 只包含键名，不包含设置值。内存加载最新确认值，同时保留队列中尚未完成的独立修改。该冲突不会永久禁用后续写入。
- 每次修改最多尝试三次 CAS 写入。持续竞争时仍拒绝保存，不降级为无条件覆盖。
- 初始化读取失败仍为只读；远端数据 schema 验证失败时，不重试写入，也不把非法快照发布给订阅者。

`SettingsStoreApi.refresh(): Promise<void>` 按队列顺序读取非密钥设置，并通知实际变化的键。刷新与待保存修改并发时，后续修改仍会按其原始基值检查冲突。旧式未实现 revision 协议的自定义后端保留原有串行快照写入，`refresh()` 不读取此类后端。

Web 在 `covel:settings` 的 storage 事件、窗口 focus 和恢复可见时刷新。配置中的地址、价格倍率、输出额度草稿遇到远端更新时保留输入，阻止自动覆盖，并提供“加载已保存值”操作。API key 的读取、写入和删除不参与上述同步或合并。

## 密钥通道边界

`keys.*` 命名空间以及注册为 `backend: "keys"` 或 `secret: true` 的条目使用独立 secrets 通道，普通后端声明不能覆盖 `keys.*` 的含义。导入选中的普通 `entries` 若包含此类条目，会在任何写入前明确拒绝；密钥必须位于 `bundle.keys`，并显式设置 `includeSecrets: true`。普通序列化和导出始终过滤已知 secret 条目。

初始化或刷新时发现普通 settings 快照携带 secret 条目，会拒绝发布或重放该快照；初始化失败保持只读并保留原文件。动态注册发现已有普通条目实际为 secret 时也会禁用写入并从普通导出排除它。系统不会自动迁移、删除或复制这类错误放置的密钥。

## 有效模型与能力来源

模型角色列表保留已配置、已保存或未配置时默认目录中的 `default` 角色。角色目录为空时禁用生成参数输入，不会创建空角色键。

世界列表的模型配置入口直接打开服务商页。窄屏先展示服务商列表，选择后显示完整详情并可返回。服务商详情每个模型只保留一个连通测试入口。

模型用途与生成参数共享实时用途目录：合并服务端配置、插件 runtime 和 `type: slot` 声明、用户设置以及已保存的绑定和参数覆盖，确保自定义用途在两个页面都能继续编辑。插件设置中的用途选项也随当前模型配置更新。旧版密钥/预设入口映射到服务商页；复合设置键映射到对应页面。引导版本号属于内部状态，不再作为常规设置展示。

世界准备页展示所选插件的全部运行阶段，并为每个 agent runtime 分别提供文本模型绑定；function runtime 的提供商用途按全部 `type: slot` 设置逐项展示，默认值优先级为用户显式覆盖、世界 `pluginSettings`、插件声明。取消用户覆盖后恢复当前世界默认值。会话左侧栏读取当前会话插件元数据，逐 runtime 编辑会话模型覆盖；缺失或不兼容的绑定会明确提示。

模型用途和生成参数以当前绑定的 provider、model、protocol 为目标；切换绑定后，旧服务端 slot 的 token 额度不再作为新模型的限制。服务商详情查询能力时也携带该连接的协议。

- `known` 或 `model-database` 且 `found: true` 的查找结果可提供模型额度。当前未覆盖的服务端目标可保留配置额度；用户显式能力覆盖优先。
- `protocol-default` 只表示协议的估计支持。其数字不能证明模型上限，页面显示“模型上限未知”，不把协议的默认 context / output 数字当成模型硬上限。
- `/api/llm-config` 的 capability 未携带完整来源信息；未知模型时不能据此区分显式模型配置和协议回退。UI 不据此宣称已知模型上限。
- 最大输出 token 编辑在失焦或 Enter 时保存，只接受正整数；已知当前额度时还必须不超过该值。留空使用服务商默认值；未知上限不会被捏造成 HTML `max`。

这些展示规则不改变模型请求协议或服务端能力解析。实际请求的 provider 默认值、执行额度和计费仍应以请求轨迹及服务商响应核对。

## 调试刷新

调试页首次选择会话、手动刷新和自动刷新都会读取会话数据，并同步侧栏中的 phase、已完成回合数和 setup runtimes。数据页展示最近成功读取时间；失败保留上一次成功结果并标注可能过期。跨会话返回的旧响应不会覆盖当前数据。自动刷新只合并最新 trace 页，保留已加载的较早页和分页游标。
