# 使用开发 Agent 创建 Covel 扩展

适用于在代码工作区协助编写插件或世界包的 Agent。本文使用当前已有接口，
不要求安装专用 skill。先阅读工作区适用的 `AGENTS.md`，再从本页选择任务入口。

## 1. 写清楚交付物

先记录玩家应能完成的操作、输入与结果，以及包的目标框架版本。
例如：“安装社区插件后，用数字表单分配属性；非法分配不写入；重启后人物数据仍存在。”
把规则、保存方式和验证结果写清楚，避免只给出“增加跑团功能”这样的宽泛目标。

## 2. 选择边界和资料

| 需求                             | 首先阅读                                                                    | 交付位置                                   |
| -------------------------------- | --------------------------------------------------------------------------- | ------------------------------------------ |
| 设定、角色、资源和开局数据       | [世界数据](../reference/world-data.md)                                      | 独立世界包                                 |
| 可复用玩法、叙事、工具或界面     | [插件作者指南](../guide/plugin-authoring.md)                                | 独立插件包                                 |
| 调整插件在某个世界的组合或默认值 | [世界数据](../reference/world-data.md)、[插件契约](../reference/plugins.md) | 世界的 `pluginPolicy` / `pluginSettings`   |
| 现有接口不能表达的通用能力       | [设计原则](../architecture/design-principles.md)、对应 reference            | 先说明缺少的公共契约，再修改框架和回归测试 |

不必通读仓库。先按任务读取教程和对应字段参考；发生矛盾时查
[代码搜索地图](../README.md#search-map) 指向的 schema、类型、实现和测试，并同步修正文档。

## 3. 做出最小可运行包

插件从[目录、校验、加载闭环](../guide/plugin-authoring.md#最小闭环目录--验证--加载)开始。
命令默认在 Covel 仓库根目录执行：

```bash
pnpm create-plugin session-notes
pnpm test:runtime -- session-notes --pretty
```

这会在用户插件目录生成带 mock cases 的插件；自定义目标目录时，按作者指南同步设置
`--target` 和测试的 `--plugins-dir`。写入逻辑使用公开工具或插件数据接口，
不要访问框架私有 store 写接口。模型输出普通 JSON 不能替代需要完成的工具调用。

世界包从 [WorldData 规范和示例](../reference/world-data.md)开始，先验证无媒体的设定、
角色和插件组合，再加入立绘、场景与本地化。不要凭教程目录名称猜测不存在的 CLI。

## 4. 从确定性验证走到玩家操作

1. 按[插件测试指南](../guide/plugin-testing.md)校验 manifest、数据和关键规则；覆盖非法输入与失败路径。
2. 打成独立 community ZIP，验证安装、重复安装、授权、实际调用、重启、卸载；不要只测仓库内置加载。
3. 涉及模型或界面时，完成[玩家流程验收](../guide/e2e-testing.md#发版前的玩家流程验收)。真实模型应记录失败、重试和最终存储结果；跳过项单独说明。
4. 本地检查通过后再运行远端 CI 或发布验证。使用隔离存档；按任务授权处理真实模型费用和外部发布。

## 5. 交付给下一位使用者

- 包里包含使用说明、所需版本、配置、权限、安装与卸载步骤。
- 说明如何观察成功结果、如何复现验证，以及实际覆盖的平台和仍存在的限制。
- 插件与世界包可独立版本化；影响公共契约时同步 reference 和兼容说明。
- 不把密钥、私人存档、日志或作者机器路径放进示例和分发包。

后续开发 skills 将复用本流程及具体任务教程；本文不改变游戏内 Agent 的运行权限。
