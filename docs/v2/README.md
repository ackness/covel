## 一套贯穿所有章节的模型

制作世界资源时，先读[世界美术方向与验收](../guide/world-art-direction.md)，再进入立绘和场景教程。
它记录三个世界各自的视觉约束、参考图编辑方式与资源交付检查。

**世界描述内容，插件实现行为，内核提供通用接口和执行规则。**

- 世界包选择设定、角色、资源、插件组合及默认配置。
- 插件通过 `capabilities`、输入输出、工具、Hook 和数据契约协作；可只写提示词，也可组合确定性函数、Agent runtime 和界面。
- 内核负责调度、校验、权限、提交和恢复。具体玩法不因被建议或被内置就必须进入内核。

每个教程沿同一条路径展开：**明确目标 → 选择边界 → 做出最小包 → 看见运行结果 → 验证失败与恢复 → 分发和升级**。
玩家先看到操作和结果；作者随后理解接口；只有需要修改执行机制时才进入架构细节。

## 怎样逐步替换

1. 先迁移“第一个插件”和“第一个世界”两条完整路径，再补玩家指南、常见任务和参考页。
2. 每次迁移交付一个可独立完成的任务：前置条件、文件、命令、预期结果、失败定位、验证和升级说明一起完成。
3. 示例按第三方包验证，禁止依靠内置 ID、特权或作者机器路径才能成功。
4. 一个契约只保留一个权威页面。教程链接参考页，skills 链接教程；旧页在新页通过验证后改为迁移入口，保留旧链接的到达路径。
5. 在本页记录已迁移入口；未完成的内容明确标注。版本和能力必须对应已验证实现，不把规划当成可用功能。
6. 逐章通过后再切换 [`docs/README.md`](../README.md) 的默认入口。历史 CHANGELOG、协议版本和包自己的版本仍保留原意。
