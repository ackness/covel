# 应用自带的功能

这一页不讲插件，讲应用本身给玩家的功能：每项是什么、在哪里找、有什么值得知道的。

## 文本和舞台两种视图

游戏界面顶部有“文本”和“舞台”两个按钮。“文本”是一页一页读的文字界面，“舞台”是带背景和立绘的全屏画面。两种视图看的是同一局游戏，随时可以切换。

![文本模式](/text-mode.webp)

舞台视图的细节见[舞台与声音](./stage.md)。

## 外观

在“设置”的“外观”里。“风格方案”决定整个界面的结构和视觉风格，选中后立即生效。下面还有配色和字体等可以继续微调；“配色模式”选浅色或深色。

在“主题库”里可以“导入主题”，导入的主题会保存在本机，并出现在风格方案的列表里。做自己的主题见[主题](../recipes/themes.md)。

设置搜索框显示键盘焦点。配置来源的分段按钮会标出当前选项。读屏软件会读出模型能力与深色模式开关的当前状态。保存、导入等操作的结果也会播报。主题只支持一种明暗模式时，切换按钮会说明原因。

## AI 创建世界

在世界选择页点“AI 创建世界”。写下“核心创意”，在“玩家体验”里选世界为哪个玩法包而做（选项就是应用里的玩法包，例如“传统故事模式”“对话模式”“低成本”），再勾选要一起生成的内容：主要角色、世界资料库、世界规则、开局配置。还可以在“补充要求”里写必须出现或要避开的内容。点“开始构筑”，应用会依次创作、检查一致性、封装成世界包。

![世界包构建](/world-package-builder.webp)

生成会消耗模型调用。如果模型长时间没有输出，可以在设置里调大“世界创作：等待模型的时间（秒）”。

应用生成的世界可以在详情页的“修改这个世界”里继续修订。写下要求，点“应用修改”。修订运行时可以点“取消”，要求会保留，方便修改后重试。

世界维度编辑器中有未保存的修改时，点“取消”、跳转到其他页面或后退时，会先询问是否放弃。选“继续编辑”保留草稿；刷新或关闭页面时由浏览器提示。提示也保护不完整的表单输入和尚未应用的 JSON；JSON 修改要先点“应用定义”，再保存。

## 准备页：选插件和玩法包

选好世界、点“进入”之后是准备页（“会话配置”）。这里决定这一局启用哪些插件。

- 顶部可以选玩法包，例如“传统故事模式”“对话模式”“低成本”“只要叙事”。选一个包，就一次启用它包含的插件；有的包也会关掉一些插件。
- “回到最小集合”只留叙事插件，以及它们和世界必需的插件，其余全部关闭。
- 下面是插件列表，可以逐个勾选，顶部显示“已选择 x/y 个插件”。
- 世界有自己的默认和推荐时，会标注“世界默认”或“世界推荐”。
- “自定义插件与高级设置”里有更细的选项。

确认之后点“开始游戏”。第一次玩，直接用世界推荐的玩法包就好。每个插件做什么，见[内置插件与功能](./index.md)。

## 换一个任务用的模型

不同的任务可以用不同的模型：比如写正文用好一点的，整理资料用便宜快速的。

- 全局设置：“设置”的“服务商与模型”里配置服务商和模型，并给每种模型用途选一个模型。第一次配置见[连接模型](../start/models.md)。
- 单个任务：在准备页，每个插件任务有“模型”选项，可以改成别的模型用途。改过之后，下一回合就用新的。

模型用途的细节见[模型用途](../reference/slots.md)。

## 重试

停止开场生成后，“已停止，本轮未提交”提示旁有“继续”，点击后才会重新生成开场。如果在回合开始前停止，刚发送的消息会退回输入框，保留同时新写的文字；可以修改后再发送。

模型偶尔会失败。应用的做法是只重做坏掉的部分，已经成功的不会丢。

- 一个任务失败时，点“重试此任务”，只重试这一项。
- 有多个失败时，点“重试失败任务”。正文和其他已完成的结果会保留。
- 重试前可以点“更换模型 / 调整参数”，换一个模型，或调低输出限制，重试用的是当前设置。
- 开局准备失败时，顶部提示会说明原因。密钥、权限、模型地址或限流问题可以点“模型设置”处理，再点“重试开局准备”，只会运行没完成的步骤。执行记录可展开查看详情，准备期间的重试统一从顶部提示发起。
- 回合失败时，顶部恢复提示会显示任务记录的原因，也可以展开查看原始错误。密钥、权限、模型地址或限流问题先点“模型设置”，处理后再重试。恢复提示显示期间，从这里重试；执行记录保留简要状态和可展开的详情。
- 密钥、权限、额度或限流问题会点明服务商。如果当前会话有多个模型用途共用它，提示也会列出这些用途，例如剧情和插件。密钥认证失败时，“模型设置”打开“服务商与模型”；修好共用的密钥后，这些用途都能用它。用途列表随当前配置变化，失败详情仍保留当时的服务商和模型。
- 应用意外中断后，未完成的任务会停下来，已保存的进度保留。只有你点“重试未完成回合”，才会发起新的尝试。

## 调试页

游戏界面的“更多”菜单里有“调试追踪”，也可以直接打开 `/debug`。它列出每一回合里各个任务的执行记录、模型调用和重试，出了问题时用来查原因。同一个菜单里还可以切换“详情视图”和“原始视图”，看更接近数据的样子。

## 界面语言和翻译世界

“设置”的“界面语言”决定按钮和标签用什么语言。目前有简体中文、English 和 Русский。标为“实验性”的语言只翻译了界面，模型读到的指令仍是英文，故事质量取决于模型。

界面语言和故事语言是两回事：一局游戏的内容语言在开局时定下，而且必须是世界已有的语言。世界只有另一种语言时，进入前会提示“要进入…世界吗？”。你也可以在世界详情页点“翻译成…”给世界加一个语言版本。

翻译由你配置的模型完成，会消耗模型调用。机器翻译完成后，最好自己检查一遍人名、地名和语气。语言的规则见[多语言](../reference/i18n.md)。

## 安装插件和世界

“设置”的“安装与管理”可以从 GitHub 或 ZIP 文件安装插件包、世界包和合集包，也可以卸载。新世界安装后立即可用，插件的安装和卸载需要重启后端才生效；第三方插件的代码还要经过会话授权，符合可信来源策略时可自动通过。详细步骤见[安装插件和世界](../start/packages.md)。

打包桌面版可以直接重启内置后端。从源码启动的桌面壳不管理外部开发服务，因此“桌面”和“安装与管理”里的重启按钮不可用；请在运行 `pnpm dev` 的终端里重启服务。

## 导出和导入设置

在“设置”的“数据”里。“导出设置”把这台设备上的设置存成一个 JSON 文件，用来备份或搬到另一台设备。默认文件里没有 API 密钥，勾选“包含 API 密钥（敏感）”才会带上，这个文件要妥善保管。

导入时先选择文件，预览里可以勾选要应用的项目，点“应用”后，选中的项目会覆盖当前的值，其余设置不变。

## 会话里的编排设置

在游戏工具栏的“更多”中打开“工作室配置”，在“加载的插件”中找到“编排”。只有一个策略提供方时自动解析，显示它的名称和自身设置入口，不需要选择或保存提供方。多个提供方时才显示“回合策略”选择框，可选“自动选择”或本局已授权的精确服务。已保存的选择暂停或不可用时仍显示，不自动换另一项；可清除选择后重新自动解析。修改“不同角色数（0–16）”与“子调用数（0–64）”可控制单次执行的委托开销，默认分别为 4 和 16，零关闭对应能力。修改从下次执行开始，刷新与分叉保留。

这些通用控件不会安装或批准插件。只有提供对应能力的插件才会使用它们。作者约定见[编排契约](../reference/plugin-extensions.md#orchestration-contracts)。

### 创建身份与分别保存

准备页“游玩身份”默认“玩家”，还可选“主持人”或“旁观者”。它只用于新会话，不改已有角色绑定；主持人不获得服务器管理权限。加载插件方案时，插件选择控件暂不可用；默认组合载入后再修改，避免覆盖刚做的选择。主持人/旁观组合不创建玩家角色，群像包要当主持人时应在准备页关闭角色创建。

“编排”现在集中显示回合策略、不同角色数、子调用数和自动推进轮数。每项单独点“保存”；策略和两种执行名额走编排接口，自动推进轮数走普通会话修改。某项失败时保留它的草稿和错误，已经成功的项继续生效，重新读取已保存资源，不承诺一起回滚。提供方的设置链接打开其自己的策略字段。多个提供方需要选精确服务；暂停或失效的选择保留，可清除，不代为启用/批准。

角色/子调用名额按每次执行计算，自动推进轮数计算每次输入之后的额外执行；零关闭对应能力。设置从下一次适用执行/输入开始，运行中链的上限已经冻结。所有游戏视图仍显示推进进度和“停止推进”，新输入也会结束旧的自动链。
