# 世界包是什么

世界包是一个文件夹，里面写着一个世界的设定和内容：它是什么样的地方，有哪些人物和规则，故事从哪里开始，以及它希望用哪些插件来玩。Covel 读入这个文件夹，就能用它开一局游戏。

世界包只有内容，没有代码。你不需要会编程就能做一个世界。

## 一个世界包里有什么

```text
my-world/
├── world.yaml           身份、语言、插件组合、角色属性
├── WORLD.md             世界观正文，模型每个回合都会读到
├── data/                可选：资料库、规则、任务、物品等数据
├── characters/          可选：预置的角色
└── media/               可选：封面、立绘、场景图
```

只有前两个文件是必需的。其余的都是可选的：没有立绘也能玩，没有预置角色也能玩。

| 文件          | 回答的问题                                                         |
| ------------- | ------------------------------------------------------------------ |
| `world.yaml`  | 这个世界叫什么，用什么语言，开局启用哪些插件，角色有哪些属性       |
| `WORLD.md`    | 这个世界是什么样的，故事从哪里开始                                 |
| `data/`       | 有哪些可以在游玩中被查到的资料，有哪些开局就存在的任务、物品、关系 |
| `characters/` | 有哪些已经设定好的人物                                             |
| `media/`      | 这个世界看起来是什么样的                                           |

## 世界和插件怎样配合

世界不实现玩法，它**选择**玩法。`world.yaml` 里的 `pluginPolicy` 写明这个世界希望启用哪些插件，例如叙事者、掷骰判定、任务日志。玩家在准备页可以调整这个选择。

世界还可以给插件准备数据。任务插件接收开局任务，行囊插件接收初始物品，好感插件接收初始关系。你把数据文件放在约定的路径上，对应的插件启用时就会读到它。

所以同一个世界可以有很不一样的玩法：只启用叙事者，它是一部互动小说；加上骰子、任务和行囊，它就是一场跑团。

## 四种做法

| 做法                      | 适合谁                                 | 怎么开始                                                                       |
| ------------------------- | -------------------------------------- | ------------------------------------------------------------------------------ |
| **在应用里用 AI 创建**    | 想快速得到一个能玩的世界               | 世界选择页的“AI 创建世界”，填写一份创作简报                                    |
| **导入 SillyTavern 内容** | 已有角色卡或世界书                     | [导入指南](./import-sillytavern.md)                                            |
| **手写文件**              | 想完全掌控内容，或者想理解世界包的结构 | [第一个世界](./first-world.md)                                                 |
| **让开发 Agent 写**       | 在代码仓库里用 Claude Code 等工具      | 仓库自带 `/create-world` 技能，见[用开发 Agent 完成任务](../agent-workflow.md) |

四种做法产出的是同一种世界包，可以互相接着改。
