# 调度

主代理启动负责人之前读这一页。它规定同时运行几个子代理、每个子代理用什么模型和 effort、中途停下了怎么办。审计范围、只读边界和记录格式不在这里定，以 [SKILL.md](../SKILL.md) 和另外两份参考为准。

effort 是模型的推理档位，从低到高是 low、medium、high、xhigh、max。档位越高，想得越多、读得越细，也越慢、越贵。

## 同时运行几个

- 同时运行的子代理默认不超过 6 个，其中重档（见下一节）不超过 4 个。用户可以在计划里改这两个数。宿主自己的上限（Claude Code 默认 20 个）只是天花板，不是目标。
- 这个数包括主代理启动的所有子代理：负责人、拆出来的轻档子任务、计划里另外安排的复核。负责人自己不再启动子代理，否则数量控制不住。
- 排队时重档在前，因为它们最耗时。有一个交回或停下，就从队列里补上下一个，不等整批结束。
- 一次搜索或一条命令就能回答的小枚举，主代理自己做，不为它启动子代理。

限制数量有三个原因：每个负责人交回后，主代理都要抽查它的记录文件，一次回来太多就查不过来；先交回的专项可以把线索交给后启动的负责人；同时运行的越多，花费的峰值越高，宿主出错时一次受影响的负责人也越多。

## 按难度选模型和 effort

| 档位 | 适合的工作 | 模型 | effort |
| --- | --- | --- | --- |
| 轻 | 结果能逐条核对的机械对照：语言文件的键和插值、插件的 `locales/` 和 `lock.json`、世界的各语言版本、文档里的命令、字段、默认值和数量与代码的对照、中英文档的逐页对照 | haiku | medium；要对照的文件很多、要连续做很久时用 high |
| 中 | 范围清楚、大多在一个模块里就能读完的工作：界面状态、内置插件逐个核对、世界包内容、加载器和作者文档 | sonnet | high；范围很小、要求写得很具体的子任务用 medium |
| 重 | 跨模块的逻辑和影响大的边界：调度和提交、挂起恢复和后台作业、存储事务、模型调用的重试和超时、前端流式状态、锁和 SSE、安全和信任边界、媒体的归属和回收，以及计划里另外安排的复核 | opus | high；用户要求更深的审查，或者上一轮在这个专项上漏读时，用 xhigh |

- 负责人不用 low：任务说明很长时，low 更容易跳过搜索、提前停下、漏掉检查。
- 不默认用 max，也不默认用 fable：花费高，收益递减。只在用户点名时用。
- 主代理自己做热路径和合并，这是重档的工作。会话的模型或 effort 低于重档时，在计划里提醒用户。

拆出轻档子任务时：

- 按报告约定里子任务的写法编号，例如把 A2 拆成 A2a（界面，中档）和 A2b（语言文件，轻档），各写各的记录文件。
- 把轻档的任务写成清单：对照哪些文件，每一行记什么，什么算不一致。它照常按问题模板记录，严重程度在汇总时由汇总负责人复核。

## 启动时怎么指定

- 每次启动子代理都明确指定模型和 effort。Claude Code 里两者都不指定时，子代理沿用会话的模型和 effort：会话开在 max，十几个子代理就全按 max 跑。
- 在 Claude Code 里用 Agent 工具，类型选 general-purpose，传 `model` 和 `effort` 两个参数。不用 Explore 或 Plan：它们不能写文件，负责人没法随读随记。也不用 fork：fork 带着主会话的整段对话，并且忽略 `model` 和 `effort`。
- 环境变量或宿主设置可能强制改掉模型或 effort，例如 `CLAUDE_CODE_EFFORT_LEVEL`。以实际生效的为准，写进计划。
- 其他宿主（例如 Codex）按自己的模型从便宜到强对应三档；不能逐个指定模型或 effort 时，在计划里写明全部用宿主默认。
- 模型写别名（haiku、sonnet、opus）。别名跟着宿主指向当前版本，这一页不用随模型更新而改。

计划的分工表给每个负责人写明档位、模型和 effort，详细版 `REPORT.md` 的“范围与边界”照抄实际用的。

## 交回之后

- 每个负责人交回时，看它的记录文件：状态行、候选问题数、证据数、有没有残留的“待补”、标了争议的有几条。结果记进计划的进度记录。
- 每次有子代理交回，顺便看一眼还在运行的记录文件；每个负责人开工约 30 分钟时也看一次，这时文件里至少要有对象清单和几条证据。长时间没有写进任何证据的，提醒它先把已经读到的写进文件。提醒可能在对方交回之后才送到，所以写明发出的时间，并说明已经交回的不用理会。
- 子代理做完就关掉，不让它空占并发名额。关之前确认它的状态行是“已交回”，并且交回之后没有再给它发消息；发过的，等它处理完、再次交回才关，否则补充的内容会写到一半。
- 轻档的结果再抽几条证据对照原文。
- **升档**：覆盖停在“部分”、抽查发现读错、或者候选问题缺反证检查时，只把没做好的那部分交给高一档的子任务，不重跑整个专项。先把 effort 提一级，还不够再换上一档的模型。原负责人已经交回，这时记录文件只有新子任务一个写入者；新内容追加在后面，标明是升档补读。

## 中途停下

宿主出错（例如连接中断、超时）让子代理停下时，它已经写进记录文件的内容都还在。

1. 先续接同一个子代理（Claude Code 里用 SendMessage 发给它）：让它读回自己的记录文件，补上还没写进去的部分，然后交回。已经写下的部分不重做。
2. 续接不了，就启动一个同档的新子代理，接手同一个记录文件，从文件里写明的进度往下做。
3. 还是不行，把这个专项标为阻塞，如实写进报告。

## 依据

这一页按 Anthropic 官方文档的建议取舍，2026 年 10 月查阅：

- [Effort](https://platform.claude.com/docs/en/build-with-claude/effort)：low 适合子代理这类简单任务；high 适合复杂推理和智能体任务；xhigh 适合超过半小时、token 以百万计的长任务；Opus 的 xhigh 和 max 留给实测确有提升的工作。Haiku 用 low 时，任务说明很长就更容易跳过搜索、提前停下、漏掉检查。
- [Claude Code 的模型配置](https://code.claude.com/docs/en/model-config)：haiku 用于简单任务，sonnet 用于日常编码，opus 用于复杂推理；high 用于需要核对、容易出边界情况的工作；max 收益递减，容易想过头。
- [Claude Code 的子代理](https://code.claude.com/docs/en/sub-agents)：调用时传的 `model` 和 `effort` 优先于子代理自己的定义；默认最多同时运行 20 个子代理。
- [成本与智能的取舍](https://platform.claude.com/docs/en/about-claude/models/optimizing-for-cost-and-intelligence)：比较完成一项任务的总花费，不比单价；小模型适合量大、结果能核对的工作；先调 effort，再换模型；拆给多个子代理只在工作能分成彼此独立的大块时划算，一条前后依赖的链，或者一个上下文装得下的工作，交给一个模型更省。

官方给一般智能体工作的起点是 opus 加它的默认档 medium。审计专门找边界情况，漏掉一个严重问题比多花的 token 更贵，所以重档从 high 起步。几轮下来，如果某个专项用 high 和用 medium 的结果没有差别，就把它降到 medium。
