# chat-mode-narrator

对话模式叙事器，重点处理角色对白、当前说话人和人物互动。

## 运行时结构

- `PLUGIN.md`：包级设置与静态提示。`runtimes/plan` 是只读的回合前函数；`runtimes/narrate` 是唯一故事 agent。
- 不依赖伴随插件。规划器只读 `scene-cast@1` 的结构化名字，故事 agent 可选读取其 `activeCastContext`；没有舞台时从上一条完整提交的 `latest-story` 和当前点名推断候选，排除所有人类座位绑定的角色。显式空名单保持空，不把全世界角色当作在场。
- 可读取 `npc-graph/rag-retriever` 提供的人物关系上下文。
- 常驻 prompt 只使用世界名称、简介和标签；由世界上下文扩展提供世界条目。
- 玩家角色卡（`<player-character>`）由 entry 注册的回合级提示段提供，排在历史之后；正文里只写块名，system prompt 不随角色卡变化。
- 可调用 `memory-search` 检索已离开当前窗口的旧对话、承诺和线索。
- `advertiseEvents: true`，可调用 `emit-event` 发射当前会话已声明的领域事件。

## 数据与行为

- 为对话模式世界生成 `outputKind: story` 的主叙事。
- 说话者一变就另起一个段落，段落带说话者名字。
- 通过 manifest relations 和默认 `narrator` 互斥。
- 暴露对白占比、回复长度和视角。舞台自己的活跃说话人数控制显著性；会话“编排”中的角色数和子调用数控制委托开销。

## 视角

`perspective` 支持 `character-first`、`character-second`、`character-third`、`omniscient`、`dm`，默认 `character-second`。玩家设置覆盖世界 `pluginSettings` 中的默认值。`character-*` 三种从玩家角色的有限视角讲述，分别用“我”“你”或角色名称呼玩家角色；`omniscient` 是全知第三人称旁白，旁白里不出现“我”和“你”；`dm` 是主持人口吻，可以用“你/你们”称呼玩家，不检查人称。只调整后续旁白，保留人物对白和玩家自主权。

## 故事段落

输出声明 `io.output.schema: contract:narrative-engine@2`，模型以 JSON 返回故事段落（`segments`：`narration`、`dialogue`、`action`，对白和动作带说话者名字），并在 `cues.present` 列出在场角色。地点变化时填写 `cues.scene`，氛围变化时填写 `cues.mood`，遵循上下文提供的情绪列表；未变化的提示省略。框架把段落文字用空行连接成 `narrativeOutput`，提交时把说话者名字解析成角色，舞台名牌直接读取段落的说话者。格式出错时框架按输出修复预算请求模型改正，只有没有任何正文时才失败。检查草稿时逐段读取段落文字。

## 开发

修改提示词后，运行覆盖 prompt 拼装和对话模式世界策略的 runtime 测试。

人物档案：叙事可通过 `list-characters` / `get-character` 查询当前会话内的完整角色资料，包括尚未出场的 NPC。身份和属性优先核对档案，历史记忆用于查询发生过的事件。查询无匹配时返回未找到错误及最接近的名字，可改用其中一个或保留未知事实。

工具结果里的 `staged` 表示改动将在回合结束时生效，仍可能被拒绝；不要等待、在正文复述或为同一改动重复调用工具。

## 输出检查

通过公开 Hook 缓冲模型草稿，检查引号外的旁白是否符合当前人称。发现问题后限次请求模型纠正，不做全局代词替换；查询时的准备说明不进入正文。正文在检查通过后整段展示，最多增加两次纠正调用。人物对白和既有历史保持原样。

查不到角色档案不代表世界设定中没有这个人物；事实依据仍由世界资料、角色档案和提示词共同约束，不用关键词检查强制模型回答“未知”。这不是通用事实验证器：复杂暗示、冲突的旧档案仍需要核对，不能把文本检查通过等同于所有故事事实都正确。

## 行囊工具

可选导入 `inventory.bag@1` 为 `check-bag`、`inventory.change@1` 为 `change-inventory`。行囊启用时，叙事可查询携带物品，并在本幕获得、支付、交出或用尽物品时先调用变更工具，再写正文，付款排在前面。调用被拒绝时叙述交易未发生；成功回答只代表暂存，提交失败仍保留故事并显示提示。未启用行囊时两个工具不出现，不增加必需插件或输入。

## 群像组合

可选的 `turn-policy@1` 服务由函数规划器通过契约调用一次，使用提供方自己的设置。只有内置回合策略时无需另选提供方；在它的设置里改 strategy。有其他提供方同时启用时，在“编排”中选择精确服务。director 借用规划器的 `plugin` 文本槽与当前请求绑定；没有 gateway 或可用槽时内置策略按点名退化，模型调用失败时独自叙事。

共享演员简报只含当前言行与明确建立的场景旁白，不重放历史段落。策略仍读取上一条故事；运行器单独提供每位演员的亲历历史，避免把私下交谈或全知叙述自动告诉新来的人。

故事 agent 保留剧情槽、模型覆盖、审查 Hook、检定、时间、事件、记忆和行囊工具，并按计划顺序逐个 `delegate` 到 `character-actor@1`。parallel 只是建议，本实现串行，演员越多耗时和费用越高。失败演员不贡献台词，其余演员与旁白照常组成一个故事；全部失败、没有演员或策略不可用时交回玩家。私下 intent 不保存。演员不继承叙事器的工具、隐藏事件或父对话。

list/random 可在主持人指示和推进后建议继续，由宿主按已提交故事执行有界自动推进。普通言行与 mention/manual 交回玩家。舞台名牌仍来自公开段落及 cues，不从 intent 推断。角色工具和可选行囊写入保留原有提交边界。

开发检查：`pnpm --filter @covel/plugin-chat-mode-narrator test`。

## 开发存档

runtime ID 变为 `chat-mode-narrator/plan` 与 `chat-mode-narrator/narrate`。重新选择指向原内联 runtime 的模型覆盖与准备绑定；丢弃针对原 runtime 的待恢复挂起项、重试任务及包含这些工作的 checkpoint，或重建受影响测试会话。旧故事仍可读，新的 latest-story 导出从下一次提交开始，不回填。普通叙事器会话和整个数据库无需重建；改变游玩身份要创建新会话。
