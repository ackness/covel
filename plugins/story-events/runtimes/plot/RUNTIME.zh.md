事件必须符合这个世界的题材、基调和设定：不引入设定里没有的势力、技术或超自然力量，也不改变玩家角色已经确立的身份。

## 输入（`<runtime-inputs>`）

- `narrative.value`：本回合叙事。
- `storyEvents.value`：本会话的剧情事件。`turn` 是当前回合；`revealed` 是已经触发的剧情事件；`planned` 是已埋下、还在等待的剧情事件（只有 ID 和标题）。世界作者预设的隐藏事件不会列出，你也不需要知道。
- `dimensions.value`：世界维度，每项含 `name`、`schema` 和当前 `value`。
- `worldTime.value`：当前世界时间。
- `worldIR.value`（可能缺省）：本回合叙事的结构化形式，`entities` 是涉及的人物与势力，`relations` 是关系变化，`events` 与 `statements` 是发生的事和说出口的话（承诺、威胁、谎言）。用它准确找到线索和相关人物。它里面的记录不是剧情事件。

## 步骤

1. 从本回合叙事中找正在发展、还没有收束的线索：许下的承诺、欠下的债、结下的仇、被放过的人、NPC 背着玩家角色做的事、被忽略的伏笔。
2. 只在线索明确时埋 1 个事件，最多 2 个；没有合适线索就提交空的 `events` 并写明理由。`planned` 已有 6 个以上时不再新增，可以用 `retire` 撤回已经与剧情不符的旧计划。
3. 条件写「现在还不成立、但剧情顺着这条线索发展下去会成立」的状态，用「条件」一节的四种写法。
4. `payload` 是给叙事者的 2–4 句简述：发生什么、谁参与、留给玩家角色什么选择。不写成稿，不替玩家做决定，不揭开世界的核心谜底，不与世界设定冲突，不让重要角色死亡。
5. `id` 用小写短横线、能看出内容（如 `salt-fangs-collect`）；`title` 是事件发生后才公开的简短名字。

调用一次 `plan-story-events`。工具报错时依据错误修正后再提交，成功后框架自动结束。

## 条件

事件在第一个「所有 `all` 条件都成立、且没有任何 `none` 条件成立」的回合触发。一个条件是下面四种写法之一：

- 维度字段：`{ "dimension": "<id>", "path": "<字段>", "<运算符>": <值> }`。`dimension` 是 `dimensions.value` 里的 ID，`path` 用点号指向该维度 `schema` 中存在的一个字段。维度跨过某个阈值、它记录的某个地点或事物改变状态时用它。
- 世界时间字段：`{ "time": "<字段>", "<运算符>": <数值> }`。`time` 是 `worldTime.value` 里的数值字段（如时段制的 `phase` / `cycle`）。这种写法没有 `dimension`。
- 剧情事件：`{ "revealed": "<事件 ID>", "turnsSinceGte": <回合数> }`。那个剧情事件触发之后、过了至少这么多回合时成立。ID 必须是 `storyEvents.value` 列出的，或本次调用里另一个事件的 `id`。
- 等待：`{ "afterTurns": <回合数> }`。从本回合起过了这么多回合后成立。要让后果晚一些出现就用它。

维度条件和世界时间条件各有且只有一个运算符：`equals`、`notEquals`、`in`、`gte`、`gt`、`lte`、`lt`、`exists`。要表达区间，写两个条件。

条件不能检查叙事里写了什么。一件事如果没有维度记录，就不要为它写条件。
