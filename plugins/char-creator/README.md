# char-creator

在开局创建玩家角色，并在故事推进中持续维护重要角色记录。

## 运行时结构

- `PLUGIN.md`：角色子系统的包级摘要。
- `runtimes/player-init/`：开局角色创建流程。
- `runtimes/character-tracker/`：叙事后发现和更新角色的 agent runtime。
- `ui/character-panel.json`：共享的右侧角色面板。

追踪从 `narrative-engine@2` 选择 `/segments`，把对白和动作与其 `speaker` 一起读取，按名册姓名或别名消歧。当前玩家消息仍是独立来源；引语中的“我”不自动等于玩家，请求和承诺不等于已经发生的状态变化。正文及历史不添加姓名前缀。

## 数据与行为

- 通过角色工具和 `character.upsert` proposal 创建、更新玩家和 NPC；由内核校验并提交。
- 角色面板直接绑定会话 World Model 的 `session.characters`，不在插件数据里镜像角色。
- 世界 schema 存在时，用它生成贴合当前世界的角色表单字段。
- 每个收集的字段（包括姓名）都必须在叙事模板中保留占位符，模型修订文案时不能把它替换为默认值。校验在创建通用表单前完成，玩家修改的答案因此能回填到开场。
- 角色名不能是世界里已有角色的名字或别名：表单的 `player-name` 校验器在提交时就拒绝，并在名字字段下说明；答案不会保存，改名后再提交即可。
- 已提交的角色表单不会让会话停在 setup：属性默认值不符合它自己的类型时，建角不写入这个默认值；玩家提交的值不再被世界的属性类型接受时，重新发出表单，仍然有效的旧答案已填好，并说明原因。
- schema 步骤失败后被玩家跳过时，不再等待 schema，只用姓名建角。

## 开发

修改表单生成、角色写入或跟踪提示词后，运行本包测试。

名册里每个角色带它的别名（`aliases`）。叙事用别名称呼的人就是该角色，追踪不会为他再建一条记录；叙事揭示了已有角色的另一个名字时，追踪用 `updates[].aliases` 把它加上。角色面板把别名显示在名字下方，只读。类型徽标按界面语言显示 `player`、`npc`、`companion` 的名称；世界自己声明的类型用世界的语言写成，照原样显示。 名册有 6000 token（估算）的预算：放不下时所有角色的 description 一起截短到 120 字，仍放不下就都省略；id、名字、别名和类型始终保留。

角色追踪只为已有角色提交 `fields` 的明确状态变化和新别名；`name`、`type`、`description` 由工具使用前的 Hook 保护，避免身份问答、转述或回忆覆写人物原始简介。新角色仍可提供简介，其他插件仍可通过公开角色工具实现有意的身份修改。
