# history-compaction

核心长篇记忆压缩插件，提供默认的 `history.compact@2` 扩展。通过宿主的补全适配器独立总结连续的较早历史前缀并保护近期对话；仅在总 token 预算或 8 段上限触发时，才合并最旧的连续摘要段。

## 运行时结构与触发

- 内核按故事（`story`）与快速（`fast`）可用输入窗口的较小值触发压缩，校验返回的源消息与替代摘要 ID，并在同一事务内持久化选择性摘要替换与消息标签。
- 源消息保留在存储中供检查与快照使用；本插件只负责摘要提示词与挑选策略，不直接写存储。
- 显式声明同契约的提供方会替换此默认实现；禁用本插件后不再运行其压缩策略，常规上下文预算裁剪仍由内核执行。

## 预算与分段规则

- **总预算与单段目标**：摘要总预算为有效窗口的 12%（下限 128、上限 8192 tokens，且不超过窗口本身）。单段目标为其源文本的 25%（下限 128 tokens，上限为窗口的 4% 或 2048 tokens，并受总预算约束）；实际输出大小决定是否需要合并，小窗口会在合并的旧前缀与新段之间分配可用预算。
- **单次摘要调用**：请求使用 `fast` 模型的可用输入上限，单条过长的源消息保留原文；输出上限设为该段预算的两倍（至少 1024 tokens）。
- **截断与中断处理**：触及输出上限而截断的回复，仅在已填满该段预算时截断至预算并标记 `truncated`；未填满却截断或因其他原因中止（finish reason 为 `other`，如回答中途被停止）均视为失败，保留原消息。

## 返回格式与失败回退

- `history.compact@2` 返回 `{ summaries: [{ messageIds, replacesSummaryIds, content, focusSections, truncated? }] }`。每个结果段要么覆盖一段连续原文前缀，要么合并若干旧摘要段，二者不混用；旧摘要合并时保留被替换摘要中最早的 ID 与时间戳以维持时序（不兼容 `@1` 提供方，已有持久化摘要仍可读）。
- 仅在无可压缩内容时返回 `null`。若尝试无法完成（模型报错或超时、返回空摘要、合并失败或请求超出输入窗口），则抛出带具体原因的错误：宿主跳过本轮压缩并在 trace 中记为 `context.compaction.failed`，连续失败 3 次后通知玩家“长篇记忆未能压缩”，后续超出阈值时每轮重试。
- 例外：若新摘要已生成、仅合并旧摘要失败，插件保留新摘要并连同 `deferred: { reason }` 返回；宿主按失败记原因，同时允许摘要暂时超出预算（最多至上限的 2 倍），留待下一回合重新合并。

## 开发与验证

- 运行策略单元测试：`pnpm --filter @covel/plugin-history-compaction test`。
- 宿主准入、输出校验与事务持久化由上下文与服务端 compactor 测试套件覆盖。

## 质量限制

**当前压缩属于有损压缩：**

- 摘要依赖 LLM 推理生成，可能按预算截断或遗漏细节，且可能误述事实或数值（原消息仍可查验）
- 自动化测试覆盖段落挑选、预算、校验与持久化边界，不代表真实模型的无损召回或响应延迟

**预算与挑选策略基于经验调优，未经形式化验证：**

- 近期对话保护与挑选策略来自开发期样本观察，不同对话长度、消息密度与模型能力可能需要不同调参
- **建议**：在生产部署前，针对实际使用的模型与典型会话长度验证摘要质量，并在关键会话中考虑人工复核。
