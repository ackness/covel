# History Compaction

This core plugin supplies the default `history.compact@1` extension. It protects recent dialogue, selects older messages, and merges them with the prior rolling summary using the host's completion adapter.

The kernel decides when history exceeds the available budget, validates the returned source message IDs, and persists the summary and message tags in one transaction. Source messages remain available for inspection and snapshots. The plugin owns the summary prompts and selection policy, and does not write storage directly.

An explicit provider of the same contract replaces this default. Disabling the plugin removes its compaction policy; ordinary context budget pruning remains a kernel operation.

Run `pnpm --filter @covel/plugin-history-compaction test` for the policy tests. Host admission, output validation, and transactional persistence are covered by the context and server compactor suites.

## Quality Limitations

**Current compaction is lossy by design:**

- The summary is generated by LLM reasoning and may truncate or omit details based on the available budget
- 10-sample validation (median 19s, max 50s) shows that the mechanism works, but does not guarantee accuracy for all edge cases
- Summary quality depends on the model used for compaction
- Observed issues in testing: attribute values may be incorrect (e.g., stealth 20→24 in one sample)

**Compaction budget and selection strategy are empirically tuned, not formally verified:**

- Recent message protection and selection policy are based on development observations
- Different conversation lengths, message densities, and model capabilities may require different tuning

**Recommendation:** Before production deployment, validate compaction quality against your actual model and typical conversation patterns. Consider implementing quality checks or manual review for critical sessions.
